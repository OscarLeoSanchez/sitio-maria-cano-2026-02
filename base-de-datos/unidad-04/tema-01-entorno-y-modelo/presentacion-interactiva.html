Instalación

Dos caminos para tener MySQL 8.4

En Windows

El servidor queda instalado como un servicio de Windows.

  • Instalador MSI, el método que recomienda el manual de MySQL.
  • Requiere Windows de 64 bits y el paquete Visual C++ 2019.
o

Con Docker

El servidor corre dentro de un contenedor.

  • Imagen oficial mysql:8.4, ya configurada.
  • Un comando crea el servidor y otro lo borra junto con su volumen de datos.
  • Requiere Docker Desktop instalado.
Los dos caminos dejan el mismo servidor MySQL 8.4 escuchando en el puerto 3306.

Instalación en Windows

Del instalador al servicio

  1. Descarga el MSI desde dev.mysql.com/downloads y ejecútalo.
  2. Al terminar, el asistente abre MySQL Configurator. El servidor no arranca hasta que se configura.
  3. En Type and Networking deja el puerto 3306.
  4. En Accounts and Roles escribe la contraseña de root; el asistente la exige.
  5. Apply Configuration crea el servicio y arranca el servidor.

Instalación con Docker

Un contenedor con MySQL 8.4

docker runcrea y arranca un contenedor
--name mysql84nombre del contenedor
-e MYSQL_ROOT_PASSWORD=cursocontraseña de root, como variable de entorno
-p 3306:3306puerto del equipo : puerto del contenedor
-den segundo plano
mysql:8.4imagen oficial, versión 8.4

Abrir la consola dentro del contenedor

docker exec -it mysql84 mysql -u root -p --default-character-set=utf8mb4

Borrar el contenedor y su volumen

docker rm -fv mysql84

-f detiene y borra el contenedor. -v borra también su volumen; sin -v los datos quedan en el disco.

El manual de MySQL advierte que escribir la contraseña en la línea de comandos es inseguro. Aquí es un contenedor desechable.

Conectar

La consola mysql abre la conexión

mysqlprograma cliente
-u rootusuario
-ppide la contraseña
-h 127.0.0.1equipo donde corre el servidor
-P 3306puerto del servidor
--default-character-set=utf8mb4juego de caracteres de la conexión
-p en minúscula pide la contraseña. -P en mayúscula indica el puerto.

Si la contraseña es correcta aparece el indicador mysql>. Cada sentencia termina en punto y coma.

Valores por defecto

  • Sin -h se conecta al equipo local.
  • Sin -P usa el puerto 3306.
  • Sin -u usa ODBC en Windows y el nombre de login en Unix.

Primera sentencia

Comprobar la conexión con VERSION()

mysql> SELECT VERSION();
mysql> SELECT CURRENT_USER();
mysql> exit
  • SELECT pide un resultado al servidor.
  • VERSION() es una función que devuelve la versión.
  • CURRENT_USER() devuelve la cuenta conectada.
  • exit cierra la consola.

Salida real de MySQL 8.4.11. El resultado puede variar según el equipo de quien lo ejecute.

Conectar con Workbench

MySQL Workbench es el cliente gráfico

Esquema rotulado, no es una captura. En MySQL un esquema es una base de datos.

  1. En la pantalla inicial pulsa + junto a MySQL Connections.
  2. Escribe un nombre y los datos: Hostname 127.0.0.1, Port 3306, Username root.
  3. Pulsa Test Connection y después OK.
  4. Haz clic en el recuadro de la conexión para abrirla.
  5. Ctrl + Enter ejecuta la sentencia del cursor. Ctrl + Shift + Enter ejecuta todas.

Scripts

Un script es un archivo de sentencias

Dentro de la consola

SOURCE saludo.sql

SOURCE busca el archivo en la carpeta desde la que abriste la consola. Con otra carpeta, escribe la ruta completa con barras /.

Desde la terminal

mysql -u root -p --default-character-set=utf8mb4 < saludo.sql

Si el archivo no empieza con USE, escribe la base: mysql -u root -p ventas < archivo.sql.

02

Qué es SQL y el modelo ventas

¿Qué dice una sentencia y qué datos hay detrás?

Los datos

Una tabla tiene filas y columnas

  • Una tabla guarda los datos de una entidad, como los clientes.
  • Una fila es un registro: un cliente.
  • Una columna es un dato de cada fila: el nombre.
  • La clave primaria identifica cada fila: id_cliente.

Los vínculos

Una clave foránea apunta a una clave primaria

Una clave foránea guarda la clave primaria de otra tabla. El pedido 101 guarda el 1 y apunta a Ana.

Lenguaje declarativo

SQL describe qué quieres

SELECT nombre, ciudad
FROM cliente
WHERE ciudad = 'Cali';

La sentencia describe el resultado. El motor decide cómo obtenerlo.

Consultas

¿Cuántas filas devuelve la consulta?

SELECT nombre, ciudad
FROM cliente
WHERE ciudad = 'Cali';

WHERE

Deja solo las filas que cumplen la condición.

La tabla cliente tiene diez filas. ¿Cuántas devuelve esta sentencia?

+--------+--------+
| nombre | ciudad |
+--------+--------+
| Laura  | Cali   |
| Pedro  | Cali   |
+--------+--------+
Dos filas: los clientes de Cali.

Familias de SQL

Cinco familias de sentencias

DDL

Data Definition Language. Define la estructura.

CREATEALTERDROP

DML

Data Manipulation Language. Cambia los datos.

INSERTUPDATEDELETE

DQL

Data Query Language. Consulta los datos.

SELECT

DCL

Data Control Language. Da y quita permisos.

GRANTREVOKE

TCL

Transaction Control Language. Confirma o deshace cambios.

START TRANSACTIONCOMMITROLLBACK
Algunos textos incluyen SELECT dentro de DML. Aquí se separa en DQL porque solo lee y no cambia nada.

Anatomía

Una sentencia se compone de cláusulas

Una sentencia reúne cláusulas. Cada una empieza con una palabra clave y usa identificadores, que son nombres de tablas y columnas.

SELECTpalabra clave: qué hacer
nombre, ciudadidentificadores: columnas que se piden
FROM clientecláusula: de qué tabla
WHERE ciudad = 'Cali'cláusula: qué filas
;cierra la sentencia
+--------+--------+
| nombre | ciudad |
+--------+--------+
| Laura  | Cali   |
| Pedro  | Cali   |
+--------+--------+

Cómo se escribe

Las palabras clave no distinguen mayúsculas

SeLeCt 1 + 1;

¿Qué devuelve SeLeCt 1 + 1;?

+-------+
| 1 + 1 |
+-------+
|     2 |
+-------+
Las palabras clave no distinguen mayúsculas.

Cómo se escribe

La convención de nombres del curso

Palabras clave

En mayúsculas: SELECT, FROM, WHERE.

Nombres

En minúsculas con guion bajo: detalle_pedido, fecha_registro.

Tablas

En singular: cliente, pedido, producto.

Claves

Con id_ y el nombre de la tabla: id_cliente, id_pedido.

Comentarios

Tres formas de escribir un comentario

-- dos guiones y un espacio: hasta el final de la línea
#almohadilla: hasta el final de la línea
/* */bloque: puede ocupar varias líneas
SELECT 1 + 1; -- guiones y un espacio
SELECT 1 + 1; # almohadilla
SELECT 1 /* varias líneas */ + 1;

Las tres sentencias devuelven 2: MySQL ignora el comentario.

Los guiones dobles exigen un espacio, un tabulador o un salto de línea después de ellos.

Comentarios

¿Qué hace MySQL con --suma?

SELECT 2 + 2 --suma
;

Los guiones dobles van pegados a la palabra suma.

¿Qué responde MySQL?

ERROR 1054 (42S22) at line 94: Unknown column 'suma' in 'field list'
MySQL lee --suma como dos menos y la columna suma, que no existe.

Resultados

¿Cuántas filas trae una sola columna?

SELECT ciudad FROM cliente;

La tabla cliente

Tiene diez clientes. Algunos viven en la misma ciudad y dos no tienen ciudad registrada.

¿Cuántas filas devuelve la consulta?

Diez: una por cliente. El resultado repite Medellín, Bogotá y Cali, y muestra NULL donde no hay ciudad.

Resultados

Un resultado es una tabla

SELECT ciudad FROM cliente;
+-----------+
| ciudad    |
+-----------+
| Medellín  |
| Bogotá    |
| Cali      |
| Medellín  |
| Bogotá    |
| Cali      |
| Medellín  |
| Bogotá    |
| NULL      |
| NULL      |
+-----------+

Filas repetidas

Medellín y Bogotá aparecen tres veces cada una. Un resultado no elimina repetidos.

NULL

Diego y Valentina no tienen ciudad registrada: la celda muestra NULL, que significa que no hay valor.

Sin orden garantizado

Sin una cláusula de orden, MySQL devuelve las filas en el orden que le resulte más cómodo.

Modelo entidad relación

La pata de gallo dice cuántos

Cada rectángulo es una entidad. La cardinalidad cuenta cuántas filas de una entidad se relacionan con una fila de la otra. La participación dice si esa relación es obligatoria: el primer símbolo es el mínimo y el segundo, el máximo.

Un cliente hace cero o muchos pedidos. Un pedido pertenece a uno y solo un cliente.

La Unidad 3 escribía estas relaciones como 1:N y N:M. La pata de gallo dibuja lo mismo con símbolos.

Si falla la conexión

Un plugin de contraseña desactivado

Un plugin de autenticación decide cómo se comprueba la contraseña de una cuenta. En 8.4 el plugin antiguo viene desactivado.

SELECT PLUGIN_NAME, PLUGIN_STATUS
FROM information_schema.PLUGINS
WHERE PLUGIN_NAME IN ('mysql_native_password',
  'caching_sha2_password');
+-----------------------+---------------+
| PLUGIN_NAME           | PLUGIN_STATUS |
+-----------------------+---------------+
| caching_sha2_password | ACTIVE        |
| mysql_native_password | DISABLED      |
+-----------------------+---------------+

information_schema es la base donde MySQL describe sus propios objetos.

Si falla la conexión

¿Se crea una cuenta con el plugin antiguo?

CREATE USER 'ana'@'%'
  IDENTIFIED WITH mysql_native_password BY 'clave1';
Una cuenta nueva usa caching_sha2_password. Para un cliente antiguo, el servidor arranca con --mysql-native-password=ON. El manual marca el plugin antiguo como obsoleto.

Con el plugin desactivado, ¿qué responde MySQL?

ERROR 1524 (HY000) at line 51: Plugin 'mysql_native_password' is not loaded
El plugin no está cargado, así que MySQL no crea la cuenta.

Si falla la conexión

El error 2061 en la primera conexión

mysql -h 127.0.0.1 -u ana -p --ssl-mode=DISABLED

TLS cifra la conexión. Con --ssl-mode=DISABLED se apaga. Sin TLS, el servidor necesita entregar su clave pública RSA para recibir la contraseña.

La contraseña de la cuenta no está en la caché del servidor tras crear la cuenta, cambiar su clave, usar RENAME USER o FLUSH PRIVILEGES, ni después de reiniciar el servidor.

La cuenta ana es nueva. ¿Qué ocurre?

ERROR 2061 (HY000): Authentication plugin 'caching_sha2_password' reported error: Authentication requires secure connection.
Con --get-server-public-key el cliente pide la clave RSA y conecta como ana@%.
