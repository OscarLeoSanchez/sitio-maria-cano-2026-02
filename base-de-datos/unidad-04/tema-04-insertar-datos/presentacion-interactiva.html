Predicción

¿Qué id recibe Sara?

En un archivo, el cliente añade at line N tras el número de error.

El primer INSERT de Sara falla con el error 1062. ¿Qué id recibe el segundo INSERT de Sara?

El error 1062 gastó el id 5 y el contador siguió: Sara quedó con el 6.
ERROR 1062 (23000): Duplicate entry 'laura@email.com' for key 'cliente.correo'

Orden de carga

El jefe se inserta antes que su equipo

empleado está vacía. Insertas a Andrés (id_jefe = 1) antes que a Gloria (id 1). ¿Qué pasa?

MySQL busca al empleado 1, no lo encuentra y rechaza la fila con el error 1452 (fk_empleado_jefe). Con Gloria cargada primero, el INSERT de Andrés funciona.

NULLdesconocido?

v acepta NULL y tiene CHECK (v >= 0). ¿Qué hace INSERT INTO prueba_check VALUES (NULL);?

El NULL entra: con NULL la condición es desconocida, y CHECK solo rechaza las filas falsas. Para exigir valor, usa NOT NULL.
El INSERT de -1 falla: ERROR 3819 (HY000): Check constraint 'prueba_check_chk_1' is violated.

Resumen

Lo que quedó de insertar datos

  • INSERTCon lista de columnas; una o varias filas.
  • SELECT, COUNT, WHEREVer la carga y comprobarla.
  • DEFAULT y NULLLo que no escribes toma el valor por defecto o NULL.
  • AUTO_INCREMENTLAST_INSERT_ID() trae el primero del lote; un UNIQUE repetido o una clave foránea inexistente gastan un id.
  • Orden de cargaEl padre antes que el hijo; el jefe antes que su equipo.
  • RestriccionesErrores 1062, 1452, 1048, 1364, 3819, 1366, 1292, 1406 y 1265.
  • CHECK y NULLEl NULL pasa: se acompaña con NOT NULL.
  • Modo estrictoUn dato inválido es un error y la fila no se guarda.

Opcional

INSERT IGNORE no arregla datos malos

El precio es DECIMAL y el INSERT IGNORE manda 'abc'. ¿Qué precio guarda MySQL para Fantasma?

MySQL guarda 0.00 y solo emite un aviso: Warning 1366: Incorrect decimal value: 'abc' for column 'precio' at row 1. INSERT IGNORE convierte el error en aviso y no corrige el dato.
