Ordenar y paginar

¿Los cinco más caros? Sin ORDER BY no hay orden

Sin ORDER BY: el orden lo elige el motor 
SELECT * FROM categoria;
Con ORDER BY: el orden se pide 
SELECT * FROM categoria
ORDER BY id_categoria;
Las categorías se insertaron con los ids 1 a 5, pero la primera consulta las devolvió por nombre. Solo ORDER BY garantiza un orden.

Ordenar y paginar

Una o varias columnas, ASC o DESC

ASC ordena de menor a mayor y es el valor por defecto. DESC ordena de mayor a menor. El segundo criterio solo actúa entre filas empatadas en el primero.
SELECT nombre, precio
FROM producto
ORDER BY nombre;
SELECT id_producto, nombre, id_categoria, precio
FROM producto
ORDER BY id_categoria, precio DESC;

Ordenar y paginar

NULL es el menor de todos

SELECT id_cliente, nombre, ciudad
FROM cliente
ORDER BY ciudad, id_cliente;

Diego y Valentina no tienen ciudad (NULL, dato que falta). Con ORDER BY ciudad ascendente, ¿dónde quedan?

Quedan primero: para ORDER BY, NULL es el menor. Con DESC quedan al final.
SELECT id_cliente, nombre, ciudad
FROM cliente
ORDER BY ciudad DESC, id_cliente;

Ordenar y paginar

Un ENUM ordena por la posición de su lista

DISTINCT deja cada valor una sola vez, sin repetidos.

SELECT DISTINCT CAST(estado AS CHAR) AS estado_texto
FROM pedido
ORDER BY estado_texto;
ORDER BY estado
con CAST a texto

CAST(estado AS CHAR) convierte el valor a texto.

SELECT DISTINCT estado
FROM pedido
ORDER BY estado;

El alfabeto empieza por cancelado. ¿Qué estado sale primero?

Sale pendiente: un ENUM ordena por la posición de su lista.

Ordenar y paginar

LIMIT corta después de ordenar

Primero se ordena por stock de menor a mayor, después se cortan las filas.

SELECT nombre, stock
FROM producto
ORDER BY stock
LIMIT 2;
Sin ORDER BY, LIMIT corta filas en un orden que MySQL no garantiza. Ordena primero y corta después.

Ordenar y paginar

Cuando el corte cae en un empate

SELECT id_producto, nombre, precio
FROM producto
ORDER BY precio DESC LIMIT 6;

Cámara y Barra de sonido cuestan 500000. ¿Quién ocupa la fila 6?

MySQL no define el orden entre empatados: puede salir cualquiera. Con LIMIT 7 entran las dos.

Ordenar y paginar

OFFSET salta filas para paginar

SELECT id_producto, nombre
FROM producto
ORDER BY id_producto
LIMIT 5 OFFSET 5;

Ordenar y paginar

MySQL evalúa las cláusulas en otro orden

SELECT se escribe primero, pero MySQL lo evalúa después de FROM y WHERE: las filas existen antes que las columnas calculadas.
El orden lógico es un modelo para razonar. MySQL puede ejecutar los pasos en otro orden mientras el resultado sea el mismo.

Ordenar y paginar

Las filas pasan cláusula por cláusula

SELECT nombre,
       precio * 0.9 AS precio_oferta
FROM producto
WHERE stock > 10
ORDER BY precio_oferta DESC
LIMIT 2;

Las cinco etapas siguen el orden lógico de evaluación.

Resumen de ordenar y paginar

Ordenar y paginar en seis ideas

Sin orden garantizado

Sin ORDER BY, el motor devuelve las filas en el orden que prefiera.

Criterios

Varias columnas, cada una con ASC o DESC. La segunda desempata a la primera.

NULL y ENUM

NULL va primero con ASC. Un ENUM ordena por posición.

Top N

ORDER BY y LIMIT juntos dan los N primeros según el criterio.

Empates

Si el corte cae en un empate, MySQL elige uno de los empatados sin avisar.

Paginación

OFFSET = (página - 1) x tamaño. Siempre con una columna única al final del orden.

Funciones

Una función de fila devuelve un valor por fila

Una función de agregación, como SUM, junta varias filas en un solo valor. Se ve al final del tema.
SELECT nombre, correo,
       CONCAT('Contacto: ', correo) AS contacto
FROM cliente;

Pedro no tiene correo (NULL). ¿Qué devuelve CONCAT para Pedro?

Devuelve NULL: basta un argumento NULL para que CONCAT devuelva NULL.

Funciones

UPPER y LOWER cambian las mayúsculas

SELECT UPPER('Bogotá') AS mayus,
       LOWER('MEDELLÍN') AS minus;

¿Qué devuelve UPPER('Bogotá')? La á lleva tilde.

UPPER pasa todas las letras a mayúsculas y conserva la tilde. LOWER hace lo contrario.

Funciones

LENGTH cuenta bytes y CHAR_LENGTH cuenta letras

SELECT LENGTH('Bogotá') AS bytes,
       CHAR_LENGTH('Bogotá') AS letras;

Bogotá tiene 6 letras y la á ocupa dos bytes en utf8mb4. ¿Qué devuelve LENGTH('Bogotá')?

Devuelve 7 bytes: cinco letras de un byte y la á de dos. CHAR_LENGTH devuelve 6.

Funciones

SUBSTRING toma un trozo del texto

SELECT SUBSTRING('Medellín', 1, 4) AS parte;

SUBSTRING(texto, inicio, largo) toma largo letras desde la posición inicio. ¿Qué devuelve?

Devuelve Mede: cuatro letras desde la posición 1. La primera posición de un texto es la 1.

Funciones

ROUND redondea el número

ROUND(precio * 1.19) da el precio con IVA del 19 %, a pesos enteros.
SELECT ROUND(2.567, 2) AS redondeo,
       ROUND(2.5) AS medio;

¿Qué devuelve ROUND(2.5), sin segundo argumento?

Devuelve 3: sin segundo argumento redondea al entero más cercano y el medio sube. ROUND(2.567, 2) deja dos decimales: 2.57.

Funciones

CEIL sube y FLOOR baja

SELECT CEIL(2.4) AS techo, FLOOR(2.4) AS piso,
       CEIL(-2.4) AS techo_neg, FLOOR(-2.4) AS piso_neg;

CEIL sube al entero siguiente. ¿Qué devuelve CEIL(-2.4)?

Devuelve -2: el entero siguiente a -2.4, hacia la derecha en la recta, es -2. FLOOR(-2.4) baja a -3.

Funciones

DATEDIFF resta dos fechas

CURDATE() devuelve solo la fecha del servidor y NOW() devuelve fecha y hora; las dos cambian cada día. Aquí se usa una fecha escrita, como '2026-12-31', para que el resultado sea siempre el mismo.
SELECT DATEDIFF('2026-12-25', '2026-12-01') AS dias,
       DATEDIFF('2026-12-01', '2026-12-25') AS al_reves;

DATEDIFF(fecha1, fecha2) da los días de fecha1 menos fecha2. ¿Qué devuelve al_reves?

Devuelve -24: la primera fecha es anterior a la segunda, así que la resta sale negativa.

Funciones

DATE_FORMAT da formato a una fecha

IN (101, 114, 125) conserva los pedidos cuyo id está en esa lista.

SELECT fecha, DATE_FORMAT(fecha, '%d/%m/%Y') AS formato
FROM pedido
WHERE id_pedido IN (101, 114, 125);

El pedido 101 tiene la fecha 2026-09-20. ¿Qué devuelve DATE_FORMAT(fecha, '%d/%m/%Y')?

Devuelve 20/09/2026: %d es el día, %m el mes y %Y el año de cuatro cifras.

Funciones

YEAR y MONTH extraen partes de una fecha

SELECT fecha, YEAR(fecha) AS anio,
       MONTH(fecha) AS mes
FROM pedido
WHERE id_pedido IN (101, 114, 125);

El pedido 101 tiene la fecha 2026-09-20. ¿Qué devuelve MONTH(fecha)?

Devuelve 9: MONTH da el número del mes. YEAR da el año, 2026.

Funciones

DATE_ADD suma días a una fecha

INTERVAL 30 DAY es una duración de 30 días que DATE_ADD suma a la fecha.
SELECT fecha,
       DATE_ADD(fecha, INTERVAL 30 DAY) AS vence
FROM pedido WHERE id_pedido IN (101, 114, 125);

El pedido 101 es del 2026-09-20. ¿Qué devuelve vence?

Devuelve 2026-10-20: septiembre tiene 30 días.

Resumen de funciones

Funciones en seis ideas

Fila y agregación

Una función de fila devuelve un valor por fila. Una de agregación, como SUM, junta varias filas en un valor.

Texto

CONCAT, UPPER, LOWER y SUBSTRING. CONCAT con NULL da NULL.

Bytes y letras

LENGTH cuenta bytes y CHAR_LENGTH cuenta letras.

Números

ROUND redondea. CEIL sube al entero siguiente y FLOOR baja al anterior, también con negativos.

Fecha fija

DATEDIFF(fin, inicio) con una fecha escrita da siempre el mismo resultado.

Formato de fecha

DATE_FORMAT con %Y, %m y %d. YEAR y MONTH extraen partes.

Decidir en la consulta

¿Qué mostrar cuando falta el dato? IFNULL

Si el valor no es NULL pasa igual; si es NULL se cambia por el reemplazo.

SELECT nombre, correo,
       IFNULL(correo, 'sin correo') AS contacto
FROM cliente;

Decidir en la consulta

COALESCE devuelve el primer valor con dato

SELECT id_empleado, nombre, id_jefe,
       COALESCE(id_jefe, id_empleado) AS responsable
FROM empleado;

Gloria no tiene jefe (id_jefe es NULL). ¿Qué devuelve COALESCE(id_jefe, id_empleado)?

Devuelve 1: el primer argumento es NULL, así que sigue con el segundo, su propio id.

Decidir en la consulta

CASE decide según condiciones

SELECT nombre, stock,
       CASE
         WHEN stock = 0 THEN 'agotado'
         WHEN stock < 5 THEN 'pocas unidades'
         ELSE 'disponible'
       END AS disponibilidad
FROM producto;

Decidir en la consulta

El CASE simple compara una expresión

SELECT id_pedido, estado,
       CASE estado
         WHEN 'pendiente' THEN 'por cobrar'
         WHEN 'pagado' THEN 'listo'
         WHEN 'enviado' THEN 'en camino'
         ELSE 'anulado'
       END AS leyenda
FROM pedido
WHERE id_pedido IN (101, 102, 105, 114);

Decidir en la consulta

Contar con SUM(CASE ...)

SELECT SUM(CASE WHEN precio >= 700000 THEN 1 ELSE 0 END) AS caros,
       SUM(CASE WHEN precio < 700000 THEN 1 ELSE 0 END) AS accesibles
FROM producto;
SUM es una función de agregación: a diferencia de las de fila, suma varias filas y devuelve un solo valor. Con CASE, cada fila aporta 1 o 0.

Reto: CASE frente a COALESCE

Ejercicio 6. CASE o COALESCE

Reto: reescribir y justificar

Reescribe este CASE con COALESCE y explica cuándo no se puede hacer.

SELECT id_cliente,
       CASE WHEN ciudad IS NULL THEN 'sin ciudad' ELSE ciudad END AS ciudad
FROM cliente;
SELECT id_cliente,
       COALESCE(ciudad, 'sin ciudad') AS ciudad
FROM cliente;

Los dos devuelven lo mismo. COALESCE solo reemplaza NULL: no sirve cuando la condición es otra, como WHEN stock = 0 o WHEN precio < 150000, ni cuando hay que distinguir un texto vacío de un NULL.

Resumen de decidir en la consulta

Decidir en la consulta en seis ideas

IFNULL

Cambia un NULL por un valor de reemplazo.

COALESCE

Devuelve el primer argumento que no es NULL, con cualquier cantidad de argumentos.

CASE buscado

Evalúa condiciones en orden y devuelve el resultado de la primera verdadera.

CASE simple

Compara una expresión con una lista de valores.

SUM(CASE ...)

Cuenta o suma solo algunas filas: cada fila aporta 1 o 0.

Cuándo usar cada uno

COALESCE solo cubre NULL. Cualquier otra condición pide CASE.

Mapa conceptual

Cómo se conecta todo

  1. FROMtabla de origen
  2. WHEREfiltra filas. Un NULL se descarta.

  4. ORDER BYordena. Una columna única al final, el desempate, fija el orden.
