Crear las tablas

¿En qué orden se crean seis tablas que se apuntan entre sí?

Claves foráneas

Una columna que apunta a otra tabla

  • FOREIGN KEY nombra la columna que apunta.
  • REFERENCES nombra la tabla y la columna a las que apunta.
  • CONSTRAINT le pone nombre a la regla, y ese nombre sale en los errores.
  • La tabla con la clave foránea es la tabla hija y la tabla a la que apunta es la tabla padre.

Primera tabla

El motor reparte los identificadores

  • El contador empieza en 1 y sube de uno en uno.
  • INSERT es la sentencia que agrega una fila. Cuando no escribe la columna, MySQL toma el número siguiente.
  • Solo una columna por tabla, y debe estar indexada.
Si el INSERT escribe el id a mano, el contador sigue desde el mayor valor: tras cargar los ids 1 a 5, el siguiente es el 6.

Claves foráneas

ON DELETE: qué pasa con los hijos

DELETE borra filas y UPDATE cambia sus valores: son sentencias DML, las que trabajan con las filas. ON DELETE decide qué pasa con las filas hijas cuando se borra el padre.

Falla provocada

Sin paréntesis, el DEFAULT no se entiende

1064 es el código de MySQL, 42000 el SQLSTATE y el resto el mensaje. MySQL señala dónde dejó de entender: CURRENT_DATE. Una expresión como valor por defecto va entre paréntesis.

El at line 6 final es parte del mensaje. Al ejecutar un archivo, el cliente añade otro at line N tras el número de error; aquí se ve como en sesión interactiva.

Tercera tabla

Una tabla que se apunta a sí misma

  • Una tabla puede tener una clave foránea hacia ella misma: es una autorreferencia.
  • La gerente no tiene jefe: su id_jefe es NULL.
  • SET NULL exige que id_jefe admita NULL.

Cuarta tabla

CHECK: una regla que cada fila cumple

Si una fila no cumple, el error 3819 nombra la restricción: chk_producto_precio.

Quinta tabla

ENUM: una lista cerrada de valores

  • ENUM guarda uno de los valores de la lista.
  • DEFAULT 'pendiente' llena el estado cuando el INSERT no lo escribe.
  • El orden de la lista fija la posición de cada valor.

Ejercicio 3. Depurar tres creaciones

Este script tiene tres errores, uno por sentencia. Di el error de cada una, en orden, y corrígela. Las seis tablas ya existen.
Solución
  1. 1064: DEFAULT CURRENT_DATE sin paréntesis. Corrige a DEFAULT (CURRENT_DATE).
  2. 1824: la tabla pedidos no existe. Corrige a REFERENCES pedido (id_pedido).
  3. 1075: una columna AUTO_INCREMENT debe ser clave. Agrega PRIMARY KEY (id_etiqueta).

Resumen

Lo que quedó de crear las tablas

  • OrdenLas tablas referenciadas se crean primero.
  • AUTO_INCREMENTEl motor reparte el identificador.
  • IF NOT EXISTSEvita el error; no cambia la estructura.
  • DEFAULT (expr)Las expresiones van entre paréntesis.
  • CHECK y ENUMReglas del dominio dentro de la tabla.
  • ON DELETE y ON UPDATERESTRICT, CASCADE o SET NULL según el negocio.
  • InnoDBEl motor que cumple las claves foráneas.
  • ALTER, DROP y SHOWCambian, borran e inspeccionan; el borrado va en orden inverso.
