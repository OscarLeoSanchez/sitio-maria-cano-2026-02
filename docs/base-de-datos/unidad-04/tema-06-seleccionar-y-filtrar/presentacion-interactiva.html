SELECT y FROM

Una expresión calcula en cada fila

  • Una expresión combina columnas, literales y operadores.
  • MySQL la calcula una vez por cada fila.
SELECT nombre, precio, precio * 0.9
FROM producto;

Sin alias, el encabezado es el texto de la expresión.

SELECT y FROM

Un alias nombra la columna del resultado

  • AS pone el nombre solo en el resultado.
  • El alias vale solo para esa consulta.
SELECT nombre, precio,
       precio * 0.9 AS precio_oferta
FROM producto;

SELECT y FROM

Un literal se repite en todas las filas

  • Un literal es un valor escrito directamente en la consulta.
  • MySQL lo repite en cada fila del resultado.
SELECT nombre, precio,
       'COP' AS moneda
FROM producto;

SELECT y FROM

DISTINCT deja cada valor una vez

SELECT DISTINCT id_categoria
FROM producto;

La tabla tiene 18 productos. ¿Cuántas filas devuelve?

Devuelve 5 filas: una por cada categoría distinta, sin importar cuántos productos tenga.

Leer errores

Un error de MySQL tiene tres partes

  • at line 59 es la línea del archivo que se ejecuta. En la consola no aparece.
  • at line 1, al final del mensaje, es la línea de la sentencia donde MySQL dejó de entender.
Sintaxis 
SELEC nombre FROM producto;
ERROR 1064 (42000) at line 59: You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'SELEC nombre FROM producto' at line 1

La sentencia empieza con SELEC, una palabra que el lenguaje no tiene. MySQL señala dónde dejó de entender.

Leer errores

Una columna que no existe

Columna inexistente
SELECT preci FROM producto;
ERROR 1054 (42S22) at line 61: Unknown column 'preci' in 'field list'

1054 nombra la columna y dónde la buscó: field list es la lista del SELECT.

Leer errores

Una tabla que no existe

Tabla inexistente
SELECT * FROM productos;
ERROR 1146 (42S02) at line 63: Table 'ventas.productos' doesn't exist

1146 nombra la base y la tabla. La tabla se llama producto, en singular.

Resumen de SELECT

SELECT en seis ideas

SELECT y FROM

Columnas que se ven y tabla de donde salen.

Asterisco

Trae todas las columnas. La lista trae solo las necesarias.

Expresiones y alias

El SELECT calcula por fila y AS nombra el resultado.

Literales

Un valor escrito en la consulta se repite en cada fila.

DISTINCT

Deja una fila por cada combinación distinta, con NULL incluido.

Errores

Filtrar con WHERE

¿Qué productos cuestan menos de 150000?

=<><><=>=
SELECT id_producto, nombre, precio
FROM producto
WHERE precio < 150000;

Solo pasan las filas donde la condición es verdadera.

Filtrar con WHERE

AND, OR y NOT tienen su propio orden

Orden de evaluación, de primero a último

1 NOT2 AND3 XOR4 OR

Sin paréntesis, AND agrupa antes que OR. Esta condición se lee así:

ciudad = 'Cali'OR
ciudad = 'Bogotá'ANDcorreo IS NOT NULL

XOR es verdadero si solo una condición lo es

SELECT TRUE XOR FALSE AS una_cierta,
       TRUE XOR TRUE AS dos_ciertas;
Ante la duda, usa paréntesis: dejan claro qué se agrupa primero.

Filtrar con WHERE

Clientes de Cali o Bogotá, con correo

SELECT id_cliente, nombre, ciudad, correo
FROM cliente
WHERE ciudad = 'Cali'
   OR ciudad = 'Bogotá'
  AND correo IS NOT NULL;

Se buscan los clientes de Cali o de Bogotá que tengan correo. IS NOT NULL deja las filas donde el correo existe. ¿Cuántas filas devuelve la consulta?

Devuelve 4 filas. AND se evalúa primero, así que la condición es Cali OR (Bogotá AND correo). Pedro vive en Cali y no tiene correo, pero entra.

Filtrar con WHERE

Los paréntesis deciden quién se evalúa primero

Sin paréntesis: 4 filas

ciudad = 'Cali'OR
ciudad = 'Bogotá'ANDcorreo IS NOT NULL

Con paréntesis: 3 filas

ciudad = 'Cali'ORciudad = 'Bogotá'
ANDcorreo IS NOT NULL
SELECT id_cliente, nombre, ciudad, correo
FROM cliente
WHERE (ciudad = 'Cali' OR ciudad = 'Bogotá')
  AND correo IS NOT NULL;

Filtrar con WHERE

= NULL nunca es verdadero

SELECT id_cliente, nombre, ciudad
FROM cliente
WHERE ciudad = NULL;

Dos clientes tienen la ciudad en NULL. ¿Cuántas filas devuelve?

Devuelve 0 filas (Empty set): ciudad = NULL da UNKNOWN en todas. Con IS NULL aparecen los 2 clientes sin ciudad.

Filtrar con WHERE

<> y NOT LIKE también dejan fuera los NULL

SELECT id_cliente, nombre, ciudad
FROM cliente
WHERE ciudad <> 'Cali';

6 filas. Con OR ciudad IS NULL son 8.

SELECT id_cliente, nombre, correo
FROM cliente
WHERE correo NOT LIKE '%@gmail.com';

Dos clientes tienen correo de gmail y dos no tienen correo (NULL). ¿Cuántas filas devuelve?

Devuelve 6 filas: los clientes con otro dominio. Los dos con correo NULL quedan fuera. Con OR correo IS NULL son 8.

Filtrar con WHERE

BETWEEN incluye los dos extremos

Equivale a fecha >= '2026-10-17' AND fecha <= '2026-10-19'.

SELECT id_pedido, fecha, estado
FROM pedido
WHERE fecha BETWEEN '2026-10-17'
                AND '2026-10-19';

Filtrar con WHERE

La trampa de BETWEEN con DATETIME

SELECT TIMESTAMP('2026-10-19 10:30:00')
         >= '2026-10-17'
   AND TIMESTAMP('2026-10-19 10:30:00')
         < '2026-10-20' AS dentro;
SELECT TIMESTAMP('2026-10-19 10:30:00')
       BETWEEN '2026-10-17'
           AND '2026-10-19' AS dentro;

Un DATETIME guarda fecha y hora: 19 de octubre, 10:30 (TIMESTAMP lo arma). ¿Entra en el BETWEEN?

Devuelve 0: '2026-10-19' es las 00:00:00 y las 10:30 quedan después. Con >= y < da 1.

Filtrar con WHERE

IN pregunta por una lista de valores

Cada valor de la lista funciona como una igualdad unida con OR.

SELECT id_producto, nombre, id_categoria
FROM producto
WHERE id_categoria IN (2, 3);

Filtrar con WHERE

LIKE y el comodín %

  • % reemplaza cero o más caracteres.
  • En verde, el texto fijo del patrón. En amarillo, lo que cubre el comodín.
SELECT id_producto, nombre
FROM producto
WHERE nombre LIKE 'Mouse%';
SELECT id_producto, nombre
FROM producto
WHERE nombre LIKE '%USB';

Filtrar con WHERE

El comodín _ cubre exactamente un carácter

  • _ reemplaza exactamente un carácter.
  • Cinco guiones bajos piden cinco caracteres: ni más ni menos.
SELECT id_producto, nombre
FROM producto
WHERE nombre LIKE '_ouse';
SELECT id_producto, nombre
FROM producto
WHERE nombre LIKE 'Mouse _____';

Filtrar con WHERE

Texto frente a número: conversión silenciosa

SELECT nombre
FROM producto
WHERE nombre = 0;

Ningún nombre de producto es el número 0. ¿Cuántas filas devuelve?

Devuelve 18 filas, todas. Cada nombre se convierte a número y un texto sin dígitos vale 0. No hay error, solo un aviso por fila (código 1292, truncó un valor al convertirlo). SHOW WARNINGS los lista.

Ejercicio 6. Tres consultas con NULL

Reto: decidir equivalencias

¿Cuáles de estas tres consultas devuelven exactamente las mismas filas? Justifica con el comportamiento de NULL.

-- Consulta 1
WHERE ciudad <> 'Cali'
-- Consulta 2
WHERE NOT (ciudad = 'Cali')
-- Consulta 3
WHERE ciudad <> 'Cali' OR ciudad IS NULL
1: 6 filas2: 6 filas3: 8 filas

Las consultas 1 y 2 son equivalentes: si ciudad es NULL, las dos condiciones dan UNKNOWN y descartan la fila. La 3 agrega los dos clientes con la ciudad en NULL.

Resumen de WHERE

WHERE en seis ideas

Filtro por fila

WHERE deja pasar solo las filas donde la condición es verdadera.

Precedencia

NOT, AND, XOR, OR. Los paréntesis cambian el agrupamiento.

Tres valores

TRUE, FALSE y UNKNOWN. UNKNOWN también se descarta.

NULL

Se busca con IS NULL. =, <> y NOT LIKE lo descartan.

BETWEEN e IN

Los extremos entran. Con DATETIME, el día final llega solo hasta las 00:00.

LIKE y tipos

% y _ son comodines. Comparar texto con número convierte el texto.
