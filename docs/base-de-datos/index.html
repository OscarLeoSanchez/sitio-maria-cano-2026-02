De qué se trata el curso

Casi todo el software que vas a construir existe para guardar datos y devolverlos después. Este curso te enseña a diseñar esa parte: cómo pasar de una situación real a un modelo, del modelo a un conjunto de tablas que no se contradicen entre sí, y de las tablas a las consultas que responden lo que el negocio pregunta.

Empezamos por qué problema resuelve una base de datos que un archivo no resuelve. Seguimos con el modelo entidad relación, que es el lenguaje con el que se dibuja la realidad antes de escribir una sola tabla. Después viene la normalización, que es el procedimiento para que un mismo dato no viva en dos lugares y termine con dos valores distintos. Cerramos con SQL, que es donde el diseño se vuelve una base de datos que funciona.

El curso es teórico-práctico. Cada modelo que dibujes lo vas a implementar y consultar en un motor real.

Unidades de aprendizaje

Unidad 1. Introducción a los sistemas de bases de datos

Resultado de aprendizaje. Conoces los elementos fundamentales de las bases de datos relacionales.

Temas:

  • Datos, información y conocimiento. Tres cosas que se confunden a diario. El dato solo, el dato en contexto y lo que permite decidir. La distinción importa porque define qué se guarda y qué se calcula.
  • Concepto de integración en la organización. Por qué una empresa termina con el mismo cliente registrado de tres formas distintas en tres áreas, y qué significa integrar esos datos en una sola fuente.
  • Beneficios y limitaciones de la base de datos. Qué ganas: control de redundancia, integridad, acceso concurrente, respaldo. Qué pagas: costo, complejidad y un punto único de falla que hay que cuidar.
  • Aplicaciones de las bases de datos. Dónde están operando ahora mismo, del punto de venta al historial clínico, y qué exigencias distintas le pone cada dominio al diseño.
  • Bases de datos frente a sistemas de archivos. La comparación que justifica todo lo demás: redundancia, dependencia entre programa y datos, y qué pasa cuando dos usuarios escriben al mismo tiempo.

Unidad 2. Modelo entidad relación

Resultado de aprendizaje. Reconoces los elementos para el modelamiento entidad relación.

Temas:

  • Componentes del modelo. Entidades, atributos y relaciones. Cómo se decide qué es una entidad y qué es apenas un atributo de otra, que es la primera decisión y la que más cuesta corregir después.
  • Representación gráfica. El diagrama entidad relación y su notación. Un modelo que se dibuja se puede discutir con quien conoce el negocio y no sabe de bases de datos.
  • Cardinalidad. Cuántas instancias de una entidad se relacionan con cuántas de la otra: uno a uno, uno a muchos, muchos a muchos. Es lo que después define las llaves foráneas y las tablas intermedias.
  • Participación. Si una entidad puede existir sin la relación o no. La diferencia entre obligatoria y opcional se traduce directamente en si una columna admite nulos.

Unidad 3. Modelo relacional

Resultado de aprendizaje. Aplicas las formas de normalización de una base de datos y construyes modelos relacionales.

Temas:

  • Del modelo entidad relación al modelo relacional. El paso de dibujo a tablas: cada entidad con su llave primaria, cada relación resuelta con llaves foráneas o con una tabla propia.
  • Formas de normalización: primera, segunda, tercera y cuarta. Un procedimiento con reglas claras para eliminar la redundancia paso a paso. Cada forma normal corrige un tipo específico de anomalía al insertar, actualizar o borrar.
  • Importancia y aplicación del proceso. Qué falla exactamente en una tabla sin normalizar. Se ve mejor con el caso concreto: el dato repetido que se actualiza en un lado y no en el otro.
  • Diseño de tablas. Tipos de datos, llaves, restricciones y valores por defecto. Las decisiones pequeñas que hacen que la base rechace por sí sola los datos que no tienen sentido.
  • Reglas de negocio e integridad de los datos. Integridad de entidad, integridad referencial y las reglas propias del dominio. Qué conviene que vigile la base de datos y qué conviene que vigile la aplicación.

Unidad 4. Lenguaje SQL

Resultado de aprendizaje. Conoces las instrucciones SQL fundamentales para la creación del modelo físico de una base de datos y las consultas sobre los datos.

Temas:

  • Definición y estructura de las instrucciones SQL. El lenguaje con el que se crea, se llena y se interroga una base de datos relacional. Sus dos caras: definir la estructura y operar sobre los datos.
  • Pasos del procesamiento de una consulta. Qué hace el motor entre que envías la consulta y recibes el resultado. Sirve para entender por qué dos consultas que devuelven lo mismo pueden tardar tiempos muy distintos.
  • Consultas sobre varias tablas. Reunir la información que el diseño separó, que es la contraparte de haber normalizado bien.
  • Operadores para la comparación de conjuntos. Preguntar por pertenencia, existencia o comparación contra un conjunto de filas en lugar de contra un valor suelto.
  • Operadores de agregación y cláusulas group by y having. Contar, sumar y promediar por grupos, y filtrar esos grupos ya calculados. Es lo que convierte una tabla de transacciones en un informe.
