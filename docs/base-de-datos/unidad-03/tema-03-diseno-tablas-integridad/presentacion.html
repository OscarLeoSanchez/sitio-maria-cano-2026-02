Cuatro llaves, dos tablas

NOT NULL, CHECK y DEFAULT

NOT NULL

Traduce la participación total de la Unidad 2 a una columna obligatoria.

CHECK

Una regla sobre la propia fila. precio > 0, cantidad > 0.

DEFAULT

Qué valor toma la columna si nadie lo especifica.

Borrar un cliente con pedidos

Reto. Empleado que se retira

Pedido gana empleado_id. Un empleado puede dejar de trabajar sin que eso borre sus pedidos atendidos. ¿Qué política, y admite nulos o no?

Lo que un CHECK no puede ver

Sí puede vigilar

CHECK (precio > 0)

Compara la columna contra un valor fijo, en la misma fila.

No puede vigilar

Que la suma de pedidos pendientes de un cliente no supere su límite de crédito.

Eso exige sumar filas de otra tabla. Le toca a la aplicación, o a un mecanismo más avanzado que un CHECK simple.

Las cuatro tablas, completas

CREATE TABLE Pedido (
    id_pedido   INT PRIMARY KEY,
    fecha       DATE NOT NULL DEFAULT CURRENT_DATE,
    cliente_id  INT NOT NULL REFERENCES Cliente(id_cliente)
                    ON DELETE RESTRICT ON UPDATE CASCADE
);

CREATE TABLE Detalle_Pedido (
    pedido_id   INT NOT NULL REFERENCES Pedido(id_pedido)
                    ON DELETE CASCADE ON UPDATE CASCADE,
    producto_id INT NOT NULL REFERENCES Producto(id_producto)
                    ON DELETE RESTRICT ON UPDATE CASCADE,
    cantidad    INT NOT NULL DEFAULT 1 CHECK (cantidad > 0),
    PRIMARY KEY (pedido_id, producto_id)
);
