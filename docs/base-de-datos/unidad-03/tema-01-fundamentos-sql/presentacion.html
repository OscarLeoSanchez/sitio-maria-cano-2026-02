¿Qué falta respecto al modelo?

Etapa 8

Comparen la tabla creada con el modelo relacional. ¿Qué se quedó por fuera?

La clave primaria. Sin ella, nada impide dos clientes con el mismo identificador.

CREATE TABLE cliente (
    id_cliente  INTEGER PRIMARY KEY,
    nombre      VARCHAR(100),
    correo      VARCHAR(150),
    ciudad      VARCHAR(80)
);

Cada restricción nace de una necesidad

Etapa 8

CREATE TABLE cliente (
    id_cliente  INTEGER PRIMARY KEY,
    nombre      VARCHAR(100) NOT NULL,
    correo      VARCHAR(150) UNIQUE,
    ciudad      VARCHAR(80)
);
  • PRIMARY KEY no se repiten identificadores
  • NOT NULL un cliente debe tener nombre
  • UNIQUE no quiero dos clientes con el mismo correo

Declarar la clave foránea

Etapa 10

CREATE TABLE producto (
    id_producto   INTEGER PRIMARY KEY,
    nombre        VARCHAR(100) NOT NULL,
    precio        DECIMAL(10,2),
    stock         INTEGER,
    id_categoria  INTEGER,

    FOREIGN KEY (id_categoria)
        REFERENCES categoria(id_categoria)
);

FOREIGN KEY es la relación del modelo, escrita en SQL

Etapa 23

SELECT pedido.id_pedido,

  • ON la condición para emparejar filas

Etapa 28

Gerencia quiere conocer los tres productos que más dinero han vendido.

  1. ¿Qué tablas hacen falta? producto y detalle_pedido
  2. ¿Cuánto produjo cada línea? cantidad * precio_unitario
  3. ¿Qué columna las conecta? id_producto
  4. ¿Qué significa “por producto”? GROUP BY
  5. ¿Qué significa “los tres que más”? ORDER BY ... DESC LIMIT 3

La consulta completa

Etapa 28

SELECT p.nombre,
       SUM(d.cantidad * d.precio_unitario) AS ventas
FROM producto p
JOIN detalle_pedido d
  ON p.id_producto = d.id_producto
GROUP BY p.id_producto, p.nombre
ORDER BY ventas DESC
LIMIT 3;
