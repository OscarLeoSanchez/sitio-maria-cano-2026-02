Qué es una base de datos, qué es un SGBD

  1. Una base de datos es un conjunto organizado de datos persistentes
  2. El SGBD (database management system) es el programa que la administra: MySQL, PostgreSQL, SQL Server, Oracle, SQLite
  3. SQL es el lenguaje común para hablarle a cualquiera de esos motores, sin aprender uno distinto por cada uno

De dónde sale SQL

  1. Nace a mediados de los 70 en System R, el proyecto de IBM que construyó el primer SGBD relacional
  2. Chamberlin y Boyce lo llamaron SEQUEL, sobre el modelo relacional de Codd (1970)
  3. Un conflicto de marca lo acortó a SQL
  4. ANSI lo estandarizó en 1986, ISO lo adoptó en 1987 como ISO/IEC 9075

SQL es declarativo, no procedimental

Describes qué resultado quieres, no los pasos exactos para conseguirlo. El motor decide cómo recorrer los datos.

SELECT * FROM PedidoPlano WHERE valor > 5000;
  1. No le dices al motor que recorra la tabla fila por fila
  2. Solo describes la condición que debe cumplir el resultado
  3. El propio motor decide, con su lógica interna, cómo conseguirlo de la forma más eficiente

Cómo se ejecuta SQL en la práctica

Cliente de terminal (psql, mysql) o programa gráfico (pgAdmin, DBeaver). Toda sentencia SQL termina en ;.

Cinco familias de instrucciones

DDL

Data definition language. CREATE, ALTER, DROP. Define la estructura, bases de datos y tablas.

DML

Data manipulation language. INSERT, UPDATE, DELETE. Cambia los datos de una tabla que ya existe.

DQL

Data query language. SELECT. Consulta datos sin modificar nada. Algunos autores lo agrupan en el DML.

DCL

Data control language. GRANT, REVOKE. Decide qué usuario puede hacer qué.

TCL

Transaction control language. COMMIT, ROLLBACK. Agrupa cambios en una unidad indivisible.

Crear una base de datos

CREATE DATABASE cafeteria;
  1. CREATE DATABASE reserva un espacio nuevo y vacío, identificado por su nombre
  2. Hay que indicarle al cliente que trabaje sobre esa base de datos activa
  3. En PostgreSQL (psql): \c cafeteria. En MySQL: USE cafeteria;
  4. DROP DATABASE cafeteria; la elimina por completo, sin posibilidad de deshacer

La tabla de trabajo, PedidoPlano

CREATE TABLE PedidoPlano (
    pedido    INT,
    cliente   VARCHAR(80),
    telefono  VARCHAR(20),
    producto  VARCHAR(80),
    valor     DECIMAL(10,2)
);

Cargar los datos con INSERT

INSERT INTO PedidoPlano (pedido, cliente, telefono, producto, valor) VALUES
    (1001, 'Ana Ruiz',  '300 111 2233', 'Café',   4500),
    (1002, 'Ana Ruiz',  '300 111 2233', 'Torta',  23400),
    (1003, 'Luis Pena', '301 444 5566', 'Café',   4500),
    (1004, 'Ana Ruiz',  '300 111 2233', 'Jugo',   6800);
  1. INTO nombra la tabla destino, seguida de la lista de columnas a llenar
  2. VALUES introduce los valores de cada fila, uno por columna, en el mismo orden
  3. El texto va entre comillas simples, los números van sin comillas

La primera consulta

SELECT * FROM PedidoPlano;
  1. SELECT dice qué columnas quieres ver, * significa todas
  2. FROM dice de qué tabla las sacas
  3. La proyección elige columnas concretas: SELECT cliente, producto FROM PedidoPlano;
  4. AS renombra una columna en el resultado sin tocar la tabla

Filtrar con WHERE

SELECT * FROM PedidoPlano WHERE cliente = 'Ana Ruiz';
SELECT * FROM PedidoPlano WHERE valor > 5000;

=, <>, <, >, <=, >=. Sin WHERE, ninguna fila se descarta.

AND, OR y NOT

BETWEEN, IN, LIKE

SELECT * FROM PedidoPlano WHERE valor BETWEEN 4000 AND 10000;
SELECT * FROM PedidoPlano WHERE producto IN ('Café', 'Torta');
SELECT * FROM PedidoPlano WHERE cliente LIKE 'Ana%';

NULL no es igual a nada

SELECT * FROM PedidoPlano WHERE descuento = NULL;    -- 0 filas, siempre
SELECT * FROM PedidoPlano WHERE descuento IS NULL;    -- forma correcta

NULL es ausencia de valor, no cero ni cadena vacía. Ni siquiera NULL = NULL es verdadero.

ORDER BY, LIMIT, FETCH FIRST

SELECT * FROM PedidoPlano ORDER BY cliente ASC, valor DESC;
SELECT * FROM PedidoPlano ORDER BY valor DESC LIMIT 1;
SELECT * FROM PedidoPlano ORDER BY valor DESC FETCH FIRST 1 ROWS ONLY;

LIMIT no es parte del estándar ISO/IEC 9075, aunque casi todo motor lo implementa igual. FETCH FIRST n ROWS ONLY sí lo es.

Funciones de agregación

SELECT COUNT(*), SUM(valor), AVG(valor), MIN(valor), MAX(valor)
FROM PedidoPlano;

UPDATE corrige tres filas a la vez

UPDATE PedidoPlano
SET telefono = '300 999 8877'
WHERE cliente = 'Ana Ruiz';
  1. UPDATE nombra la tabla que cambia, PedidoPlano
  2. SET nombra la columna y, después del =, el valor nuevo
  3. WHERE filtra a qué filas se les aplica el cambio, igual que en SELECT

DELETE y lo que se pierde con la fila

DELETE FROM PedidoPlano WHERE pedido = 1003;

Sin una tabla Cliente separada, borrar el pedido de Luis Pena borra también su único registro de nombre y teléfono en toda la base de datos.

Borrar una tabla completa, DROP TABLE

DROP TABLE PedidoPlano;

DELETE vacía una tabla que sigue existiendo. DROP TABLE es DDL, hace desaparecer la tabla misma, estructura y datos, sin ROLLBACK posible.

El riesgo de olvidar el WHERE

UPDATE PedidoPlano SET valor = valor * 0.9;   -- actualiza las CUATRO filas
DELETE FROM PedidoPlano;                       -- borra las CUATRO filas

Ninguna de las dos sentencias es inválida. El motor las ejecuta sin queja, y esa es la razón para revisar dos veces el WHERE antes de ejecutar contra datos reales.

El orden real de ejecución

Una consulta dentro de otra

SELECT pedido, producto, valor
FROM PedidoPlano
WHERE valor > (SELECT AVG(valor) FROM PedidoPlano);

El motor resuelve primero la subconsulta entre paréntesis, y usa ese número para filtrar la consulta externa.
