Base de datos. Taller en equipos

Del modelo entidad relación al SQL

Cada equipo elige un caso, lo modela como diagrama entidad relación, lo convierte en modelo relacional y termina escribiendo el SQL que crea las tablas. El recorrido completo que va del enunciado en prosa a la base de datos que ya existe.

Cómo se trabaja

El equipo recibe un enunciado de negocio, como el que entregaría un cliente real, y lo lleva hasta el CREATE TABLE sin que nadie le marque el camino.

1

Elijan un caso

Del tablero de abajo, un caso por equipo. Dos equipos no deberían tomar el mismo. Lean el enunciado completo antes de decidir.

2

Diagrama entidad relación

Entidades, atributos clasificados, relaciones con cardinalidad y participación. En notación de Chen o de pata de gallo, pero una sola.

3

Modelo relacional

Conviertan el diagrama en tablas: llaves primarias, llaves foráneas, tablas intermedias para las relaciones N:M y decisiones sobre atributos multivaluados y compuestos.

4

SQL

Escriban el guion de CREATE TABLE con tipos, llaves y restricciones, más unos INSERT de prueba y dos o tres SELECT que respondan preguntas del negocio.

Qué entrega cada equipo

  1. El diagrama entidad relación, dibujado en app.diagrams.net (draw.io), Excalidraw o a mano en una foto legible.
  2. El esquema relacional escrito con la notación de texto que ya conocen, una línea por tabla, con la llave primaria subrayada o marcada y las llaves foráneas señaladas. Por ejemplo: 
    Cliente (numero_cliente, saldo, limite_credito, descuento)
DireccionEnvio (numero_cliente, consecutivo, numero, calle, comuna, ciudad)
    numero_cliente es llave foránea hacia Cliente
  3. Un archivo .sql que se pueda ejecutar de arriba abajo sin errores en el motor que usan en clase. Debe crear todas las tablas en el orden correcto, insertar datos de ejemplo y correr las consultas.
  4. Una lista corta de supuestos. Todos los enunciados tienen huecos a propósito. Cuando el equipo decida algo que el texto no dice, lo anota con una línea de justificación.

Sobre los huecos del enunciado. Ningún cliente entrega requisitos completos. Parte del ejercicio es detectar lo que falta, decidir con criterio y dejarlo escrito. Un supuesto razonable y justificado vale más que una pregunta sin responder. Lo que no vale es inventar entidades que el negocio no necesita.

Reglas para el SQL

  • Toda tabla tiene llave primaria declarada. Si es compuesta, se declara con PRIMARY KEY (a, b).
  • Toda llave foránea se declara con FOREIGN KEY y REFERENCES. No basta con que la columna se llame igual.
  • Las reglas del negocio que caben en una restricción van como restricción: NOT NULL, UNIQUE, CHECK. Si el enunciado dice que un límite no supera cierto valor, eso es un CHECK.
  • Las tablas se crean en un orden que respete las dependencias: primero las que no referencian a nadie.
  • Nombres de tablas y columnas sin tildes, sin eñes ni espacios, en un solo idioma y con un solo estilo (snake_case o PascalCase, no los dos).

Caso 1

Carreteras

Infraestructura vial

Diseñen el esquema entidad relación de una base de datos que contenga la información sobre todas las carreteras del país, sabiendo que se deben cumplir las siguientes especificaciones:

  • Las carreteras están divididas en varias categorías: locales, comerciales, regionales, nacionales, autovías, entre otras.
  • Las carreteras se dividen en tramos. Un tramo siempre pertenece a una única carretera y no puede cambiar de carretera.
  • Un tramo puede pasar por varias comunas. Interesa conocer el kilómetro de la carretera y la comuna donde empieza el tramo y donde termina.
  • Para los tramos que suponen principio o final de carretera, interesa saber si la carretera concluye físicamente o si confluye en otra carretera. En este segundo caso, interesa conocer con qué carretera confluye y en qué kilómetro, tramo y comuna.

Pistas para el equipo. "Un tramo siempre pertenece a una única carretera y no puede cambiar de carretera" es una frase que decide si Tramo es una entidad fuerte o débil. La confluencia es una relación entre carreteras, es decir, una relación de la entidad consigo misma, con atributos propios.

Caso 2

Sistema de vuelos

Transporte aéreo

Obtengan el diagrama entidad relación de un sistema de control de vuelos adaptado a las siguientes reglas de gestión. Indiquen las entidades, las relaciones y demás elementos que se deducen de cada regla:

  1. De cada aeropuerto se conoce su código, nombre, ciudad y país.
  2. En cada aeropuerto pueden tomar tierra diversos modelos de aviones. El modelo de un avión determina su capacidad, es decir, el número de plazas.
  3. En cada aeropuerto existe una colección de programas de vuelo. En cada programa de vuelo se indica el número de vuelo, la línea aérea y los días de la semana en que existe dicho vuelo.
  4. Cada programa de vuelo despega de un aeropuerto y aterriza en otro.
  5. Los números de vuelo son únicos para todo el mundo.
  6. En cada aeropuerto hay múltiples aterrizajes y despegues. Todos los aeropuertos contemplados están en activo, es decir, tienen algún aterrizaje y algún despegue.
  7. Cada vuelo realizado pertenece a un cierto programa de vuelo. De cada vuelo se quiere conocer su fecha, las plazas vacías y el modelo de avión utilizado.
  8. Algunos programas de vuelo incorporan escalas técnicas intermedias entre los aeropuertos de salida y de llegada. Se entiende por escala técnica un aterrizaje y despegue consecutivos sin altas o bajas de pasajeros.
  9. De cada vuelo se quieren conocer las escalas técnicas ordenadas, asignándole a cada una un número de orden.

Por ejemplo, el programa de vuelo 555 de Iberia, con vuelos los lunes y jueves, despega de Barajas (Madrid, España) y aterriza en Caudell (Sydney, Australia) con las siguientes escalas técnicas: 1. Los Pradiños (Sao Paulo, Brasil), 2. El Emperador (Santiago, Chile) y 3. Saint Kitts (Auckland, Nueva Zelanda).

Pregunta adicional

¿Qué cambios se producirían en el modelo si en las escalas pudiesen bajar o subir pasajeros? Expliquen cómo se podría representar esta nueva situación.

Pistas para el equipo. El aeropuerto participa en varias relaciones distintas con el programa de vuelo: de origen, de destino y de escala. Son relaciones diferentes, no una sola. La regla 6 habla de participación total. Los días de la semana son un atributo multivaluado.

Caso 3

Olimpíadas

Eventos deportivos

Las sedes olímpicas se dividen en complejos deportivos. Los complejos deportivos se subdividen en aquellos en los que se desarrolla un único deporte y los polideportivos. Los complejos polideportivos tienen áreas designadas para cada deporte, con un indicador de localización (por ejemplo: centro, esquina noreste). Un complejo tiene una localización, un jefe de organización individual y un área total ocupada.

Los dos tipos de complejos, de deporte único y polideportivo, tendrán diferentes tipos de información. Para cada tipo de sede se conservará el número de complejos junto con su presupuesto aproximado.

Cada complejo celebra una serie de eventos (por ejemplo, la pista del estadio puede celebrar muchas carreras distintas). Para cada evento está prevista una fecha, duración, número de participantes y número de comisarios. Se conservará una lista de todos los comisarios junto con la lista de los eventos en los que esté involucrado cada uno, ya sea cumpliendo la tarea de juez o de observador. Tanto para cada evento como para el mantenimiento se necesitará cierto equipamiento (por ejemplo: arcos, pértigas, barras paralelas).

Pistas para el equipo. Aquí aparece una jerarquía: complejo de deporte único y polideportivo son especializaciones de complejo. Decidan cómo pasarla a tablas, con una tabla por subtipo, una tabla única con columnas opcionales o las tres, y justifiquen la elección. El rol del comisario en un evento (juez u observador) es un atributo de la relación.

Caso 4

Educando S.A.

Compras, almacén e inventario

En la empresa Educando S.A. se lleva control de sus bienes y servicios. El interés primario es que los bienes se manejen de forma rápida y con el menor grado de error. Para esto, quien maneja la sección de Bienes y Suministros plantea las siguientes condiciones del negocio para la construcción de una base de datos.

Área de compras

  • La sección está dividida en tres áreas: compras, almacén e inventario.
  • Recibe las solicitudes de compras de las diferentes áreas de la empresa.
  • Cada solicitud tiene un responsable.
  • Cada solicitud es autorizada por el jefe del área y posteriormente por el director financiero.
  • Quien realiza una solicitud puede ser responsable de uno o varios centros de costos, con la salvedad de que como empleado solo está adscrito a uno.
  • De la solicitud se debe diligenciar la siguiente información: número de la solicitud (consecutivo), fecha, responsable (nombre y cédula), centro de costos y rubro presupuestal del cual se descargará la compra. En cada solicitud se pueden discriminar uno o muchos ítems con la siguiente información: ítem, nombre del bien, cantidad solicitada, unidad de medida del bien, valor unitario y valor total. Cada solicitud debe ser totalizada.
  • Cada bien es identificado por un código universal que es único, y es de carácter devolutivo (suministro) o un bien inmueble.
  • Una vez diligenciada, la solicitud es remitida al área de compras para realizar su correspondiente cotización.
  • Las cotizaciones se realizan con uno o varios proveedores de los bienes solicitados.
  • Una vez la cotización definitiva está lista, se crea una orden contractual que maneja la siguiente información: número de la orden contractual, NIT y nombre del proveedor al cual se le va a realizar la compra, fecha de la orden, monto total de la orden y fecha de entrega. Cada orden puede tener asociados uno o varios ítems de la solicitud o solicitudes que van a ser despachadas. Cada ítem tiene la siguiente información: nombre del bien, cantidad solicitada, cantidad despachada, unidad de medida del bien, valor unitario y valor total.
  • La orden de compra es aprobada por el director financiero para que sea enviada al proveedor elegido.

Área de almacén

  • Su función principal es recibir los bienes que llegan de los proveedores y distribuirlos a las áreas que realizaron las solicitudes de compra.
  • Cuando un proveedor llega con mercancía, hace una entrega física de los bienes, que se comparan con la factura que entrega y con la orden de compra correspondiente. Si todo coincide, se registra una entrada de almacén por cada factura relacionada, con la siguiente información: número de entrada, fecha, número de factura, proveedor, total de bienes y valor total (los totales deben coincidir con los de la factura). Adjunto a esta se discriminan los ítems recibidos con la siguiente información: nombre del bien y cantidad entregada.
  • Cuando el almacén decide despachar los bienes a las áreas solicitantes, registra cada una de las entregas en salidas de almacén con la siguiente información: número de salida, empleado responsable del bien a entregar, fecha de salida y fecha de entrega. Por cada entrega se detalla cada uno de los ítems con la siguiente información: nombre del bien y cantidad entregada.
  • Una entrada de almacén puede generar muchas salidas de almacén. Por ejemplo, pueden ingresar 500 pacas de papel higiénico, pero como se deben repartir entre varias áreas, cada una requiere una salida de almacén.

Área de inventarios

  • Es la encargada de administrar y controlar la ubicación de los bienes dentro de la empresa. Por esto, antes de que el bien salga del almacén debe ser codificado con un código único que lo haga identificable dentro de la empresa.
  • La ubicación del bien se identifica con la siguiente información: responsable del bien, fecha de entrega y dirección del bien (ubicación).

Pistas para el equipo. Es el caso con más entidades. Empiecen por el flujo: solicitud, cotización, orden, entrada, salida. Cada documento tiene una cabecera y un detalle de ítems, un patrón que se repite y que conviene resolver una vez y reutilizar. Distingan el bien como catálogo (código universal) del bien como unidad física inventariada (código interno).

Caso 5

Torneo de tenis Grand Slam

Deportes y competencias

El sistema debe memorizar todos los encuentros que se han desarrollado desde que existe el torneo, así como las características de estos que se describen a continuación.

Descripción

El Grand Slam se compone de cuatro torneos anuales que se celebran en Gran Bretaña, Estados Unidos, Francia y Australia. En cada país se pueden desarrollar en distintos lugares (por ejemplo, en Estados Unidos puede desarrollarse en Forest Hills o en Flushing Meadows).

Cada partido tiene asociado un premio de consolación para el perdedor, que dependerá de la fase en que se encuentre el torneo (por ejemplo, el perdedor de octavos de final puede ganar 5.000 dólares). El ganador de la final recibirá el premio correspondiente al torneo.

Cada torneo tiene cinco modalidades: individual masculino, individual femenino, dobles masculino, dobles femenino y dobles mixtos.

También hay que tener en cuenta la nacionalidad de un jugador, de forma que este puede ser apátrida o tener varias nacionalidades.

Preguntas que el sistema debe responder

  1. Dado un año y un torneo, la composición y el resultado de los partidos.
  2. La lista de árbitros que participaron en el torneo.
  3. Las ganancias percibidas en premios por un jugador a lo largo del torneo.
  4. La lista de entrenadores que han entrenado a un jugador a lo largo del torneo y las fechas en que lo hicieron.

Ejemplos de lo que debe poder registrarse

  1. Connors ganó a Gerulaitis en Roland Garros en 1979, en cuartos de final de individuales masculinos, por 6-3, 4-6, 7-5, 6-0.
  2. El señor Wilkinson arbitró ese partido.
  3. Alemania ha ganado dos veces los individuales masculinos de Wimbledon. Borg ha ganado 2.000.000 de dólares a lo largo de su participación en el Grand Slam.
  4. El ganador de Roland Garros de 1987 ganó 20.000 dólares.
  5. Noah ha jugado cuatro veces en dobles mixtos con Mandlikova.

Pistas para el equipo. Un partido lo juegan jugadores en individuales y parejas en dobles. Decidan cómo representar al participante de un partido para que las dos cosas quepan en el mismo modelo. El resultado por sets es un detalle del partido. La relación entre entrenador y jugador tiene fechas, así que no es una simple llave foránea. Verifiquen que las cinco frases de ejemplo se puedan insertar en sus tablas.

Caso 6

Cartelera de cine

Entretenimiento y sitios web

Se desea crear un sitio web con información referente a las películas en cartelera en las salas de los cines de una ciudad.

De cada película se almacena una ficha con su título de distribución, su título original, su género, el idioma original, si tiene subtítulos en español o no, los países de origen, el año de producción, la URL del sitio web de la película, la duración (en horas y minutos), la calificación (apta para todo público, mayores de 9 años, mayores de 15 años, mayores de 18 años), la fecha de estreno en la ciudad, un resumen y un identificador de la película. De cada película interesa conocer la lista de directores y el reparto, es decir, para cada actor que trabaja en ella, el nombre de todos los personajes que interpreta.

Además interesa disponer de información sobre los directores y actores que trabajan en cada película. De ambos se conoce su nombre (que los identifica) y su nacionalidad. También se desea conocer la cantidad de películas en las que dirigieron o actuaron. Tengan en cuenta que hay personas que cumplen los dos roles.

Los cines pueden tener más de una sala, y cada semana cada uno de los cines envía la cartelera para dicha semana con el detalle de las funciones. Para cada función se conoce el día de la semana y la hora de comienzo, y obviamente la sala y la película que exhibe. De cada sala se sabe el nombre, un número que la identifica dentro del cine y la cantidad de butacas que posee. De cada cine se conoce el nombre que lo identifica, su dirección y el teléfono para consultas.

Algunos cines cuentan con promociones. Estas promociones dependen de la función. Por ejemplo: de lunes a jueves antes de las 18:00, 50% de descuento en cierta sala de cierto cine para cierta película; en la función del lunes a las 14:00 para cierta película en cierta sala no se cobra a los escolares con uniforme. De cada promoción se conoce una descripción y el descuento que aplica.

Además del resumen de la película que se incluye en la ficha, interesa mostrar la opinión de las personas que la vieron. De cada opinión se conoce el nombre de la persona que la realiza, su edad, la fecha en que registró su opinión, la calificación que le dio a la película (obra maestra, muy buena, buena, regular, mala) y el comentario propiamente dicho. A cada opinión se le asigna un número que la identifica respecto de la película sobre la cual opina.

Pistas para el equipo. La sala se identifica dentro del cine y la opinión se identifica dentro de la película: dos entidades débiles. Una misma persona puede ser director y actor, así que Persona es una sola tabla con dos relaciones distintas hacia Pelicula. La cantidad de películas de una persona es un atributo derivado y no se guarda. La calificación tiene un conjunto cerrado de valores, que en SQL es un CHECK.

Cómo debe verse el SQL

Un fragmento mínimo, tomado de un caso distinto a los ocho de arriba, para fijar el estilo esperado. Fíjense en el orden de creación, en las restricciones con nombre y en la tabla intermedia con llave compuesta. 

-- 1. Tablas que no dependen de nadie
CREATE TABLE autor (
    id_autor      INTEGER      PRIMARY KEY,
    nombre        VARCHAR(120) NOT NULL,
    nacionalidad  VARCHAR(60)
);

CREATE TABLE libro (
    isbn          CHAR(13)     PRIMARY KEY,
    titulo        VARCHAR(200) NOT NULL,
    anio          INTEGER,
    CONSTRAINT ck_libro_anio CHECK (anio >= 1450)
);

-- 2. Tabla intermedia de la relacion N:M, con atributo propio
CREATE TABLE escribe (
    id_autor      INTEGER  NOT NULL,
    isbn          CHAR(13) NOT NULL,
    orden_firma   INTEGER  NOT NULL,
    CONSTRAINT pk_escribe PRIMARY KEY (id_autor, isbn),
    CONSTRAINT fk_escribe_autor FOREIGN KEY (id_autor) REFERENCES autor (id_autor),
    CONSTRAINT fk_escribe_libro FOREIGN KEY (isbn)     REFERENCES libro (isbn)
);

-- 3. Datos de prueba
INSERT INTO autor VALUES (1, 'Gabriel Garcia Marquez', 'Colombia');
INSERT INTO libro VALUES ('9780060883287', 'Cien anos de soledad', 1967);
INSERT INTO escribe VALUES (1, '9780060883287', 1);

-- 4. Una consulta que responde una pregunta del negocio
SELECT a.nombre, l.titulo, l.anio
FROM autor a
JOIN escribe e ON e.id_autor = a.id_autor
JOIN libro l   ON l.isbn = e.isbn
ORDER BY l.anio;

Sustentación. Cada equipo presenta su caso en unos minutos: el diagrama, dos decisiones de diseño que les costaron y el SQL corriendo en vivo. Los demás equipos preguntan. La pregunta más frecuente es "¿y por qué no lo hicieron de la otra forma?", así que lleguen con la respuesta preparada.
