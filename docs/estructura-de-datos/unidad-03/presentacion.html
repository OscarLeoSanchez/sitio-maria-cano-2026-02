Preámbulo

Cinco ideas que atraviesan los cinco temas, explicadas una sola vez antes de usarlas. Cada una muestra cómo se comporta en la JVM y en CPython cuando la diferencia importa.

Memoria estática y memoria dinámica

La memoria estática de un arreglo se reserva completa desde el arranque. La memoria dinámica de una lista enlazada se pide nodo por nodo, en el momento exacto en que cada nodo se crea, mientras el programa sigue corriendo.

Qué es una referencia

Una referencia es una variable que guarda la dirección de un objeto, no el objeto mismo. Cuando una referencia todavía no apunta a nada, su valor es null en Java o None en Python.

Notación O en esta unidad

Notación Qué significa Ejemplo de esta unidad
O(1), constante El trabajo no cambia sin importar cuántos datos haya Insertar en la cabeza de una lista enlazada
O(n), lineal El trabajo crece en proporción directa a la cantidad de datos Recorrer una lista enlazada o visitar todos los vértices de un grafo
O(log n), logarítmica El trabajo crece mucho más lento que los datos Buscar en un árbol binario de búsqueda balanceado

O(log n) es nueva en esta unidad. Un árbol balanceado descarta la mitad de los nodos restantes en cada comparación, así que la altura, y con ella el trabajo, crece con el logaritmo del tamaño.

Quién libera la memoria

JVM

El recolector de basura administra la memoria dinámica de forma automática, identifica qué objetos ya no tienen ninguna referencia viva apuntándolos y libera ese espacio.

CPython

Cada objeto lleva un contador de referencias. Cuando ese contador llega a cero, CPython libera el objeto de inmediato, sin esperar a un recolector aparte.

Un ciclo de referencias, un grupo de objetos que se apuntan entre sí en círculo, nunca baja a cero por conteo simple. Por eso CPython añade un recolector de ciclos aparte, expuesto en el módulo gc, además del conteo de referencias que consulta sys.getrefcount.

Bloque 1. Listas enlazadas

Bloque 1

De la memoria contigua del arreglo a los nodos dispersos que se unen con un puntero explícito.

Qué es una lista enlazada

Una lista enlazada es una secuencia de nodos donde cada nodo guarda un dato y una referencia al nodo siguiente. El arreglo calcula la dirección de cualquier índice con una multiplicación; la lista no tiene esa aritmética, así que para llegar a un nodo hay que caminar desde el principio.

El nodo: la pieza que se repite

Toda la unidad repite esta pieza, un dato y una o más referencias a otros nodos, y la estructura cambia según cuántas referencias tenga cada nodo. El nodo no expone operaciones propias. Insertar, eliminar o recorrer vive en la clase que lo envuelve.

Código: clase Nodo

Java

public class Nodo {
    Object dato;
    Nodo siguiente;

    public Nodo(Object dato) {
        this.dato = dato;
        this.siguiente = null;
    }
}

Python

class Nodo:
    def __init__(self, dato):
        self.dato = dato
        self.siguiente = None

En Java, un campo de referencia ya empieza en null, así que this.siguiente = null solo deja explícita la intención. En Python la asignación a None es obligatoria, porque un atributo no existe hasta que se le asigna un valor.

Insertar en la cabeza: la operación barata

Insertar en la cabeza toca únicamente el nodo nuevo y la referencia de la cabeza. Sin importar cuántos nodos tenga la lista, el costo es O(1).

Código: insertarInicio

Java

public void insertarInicio(Object dato) {
    Nodo nuevo = new Nodo(dato);
    nuevo.siguiente = cabeza;
    cabeza = nuevo;
    tamaño++;
}

Python

def insertar_inicio(self, dato):
    nuevo = Nodo(dato)
    nuevo.siguiente = self._cabeza
    self._cabeza = nuevo
    self._tamaño += 1

Ninguna de las dos versiones recorre la lista, porque solo hace tres asignaciones y suma un contador, haya tres nodos o tres millones detrás. El guion bajo de _cabeza marca en Python un atributo interno, lo mismo que private en la clase ListaEnlazada de Java.

O(1) insertar en la cabeza, sin importar el tamaño

2 referencias que cambian: nuevo.siguiente y cabeza

Insertar al final: cuando toca caminar toda la lista

insertarFinal recorre toda la lista para encontrar el nodo cuyo siguiente es null. El costo crece con el tamaño de la lista, O(n), justo lo contrario de insertarInicio.

Complejidad de la lista simple

Operación Costo
insertarInicio / eliminarInicio O(1)
insertarFinal / eliminarFinal O(n)
insertarEn(k) / eliminarEn(k) O(n)
Acceder a la posición k O(n)

Ninguna posición que no sea la cabeza tiene atajo. A diferencia del arreglo, una lista enlazada no puede calcular una dirección de memoria, tiene que caminar hasta llegar.

Eliminar en una posición cualquiera

El costo se divide en dos partes. Caminar hasta el nodo anterior a la posición pedida cuesta O(n), pero el reenlace en sí mismo es O(1), sin importar cuántos nodos tenga la lista detrás.

La lista doblemente enlazada

Caso de uso: el historial de navegación de un navegador, o el deshacer y rehacer de un editor. Cada estado guarda su anterior y su siguiente; retroceder mueve el puntero a anterior y avanzar lo mueve a siguiente, sin recorrer nada ni perder el resto del historial.

La fuga de memoria del enlace roto a medias

El código fuente de OpenJDK para java.util.LinkedList limpia el dato y los dos punteros del nodo que desconecta en unlink, y en clear() deja un comentario que explica que cortar esos enlaces libera la memoria aunque un iterador todavía alcance los nodos.

Lista circular: el final que vuelve al principio

Una lista circular cambia una sola regla. El último nodo ya no apunta a null, apunta de vuelta a la cabeza. La secuencia deja de tener un final visible.

La trampa del recorrido infinito

Caso de uso: una lista de reproducción que vuelve a la primera canción cuando termina la última, o un planificador que reparte turnos de procesador entre varias tareas por round robin. En los dos casos el ciclo es la regla, no una excepción que haya que simular con un módulo sobre un arreglo.

Arreglo contra lista enlazada: la comparación completa

Operación Arreglo Lista enlazada
Acceso por índice O(1) O(n)
Insertar / eliminar en la cabeza O(n) O(1)
Insertar al final O(1) amortizado O(n), o O(1) con ultimo
Eliminar al final O(1) O(n) en lista simple, O(1) en lista doble
Recorrido completo O(n) O(n)

Si la operación que más se repite es leer por índice, gana el arreglo. Si es insertar o eliminar en la cabeza, o en un nodo del que ya tienes referencia directa, gana la lista enlazada, sobre todo la doble.

Bloque 2. Pilas y colas con listas enlazadas

Bloque 2

El mismo contrato de siempre, ahora construido sobre nodos encadenados en vez de un arreglo.

El contrato que no cambia

Pila y Cola conservan los mismos ocho métodos que ya usaste sobre arreglo. Lo único que cambia es qué hay detrás de cada método, y ahora esa respuesta es el mismo Nodo encadenado.

La pila enlazada: siempre por la cabeza

La cima de la pila es la cabeza de la lista. Apilar es exactamente insertarInicio, así que la pila enlazada nunca necesita el puntero ultimo ni recorre un solo nodo.

La operación desapilar

desapilar deja eliminado.siguiente = null antes de devolver el dato. Es la limpieza que evita que el nodo que sale quede como puente hacia el resto de la pila.

Pila enlazada en Java y en Python

Java

public void apilar(Object elemento) {
    Nodo nuevo = new Nodo(elemento);
    nuevo.siguiente = cabeza;
    cabeza = nuevo;
}
public Object desapilar() {
    if (estaVacia()) throw new
        IllegalStateException("pila vacia");
    Nodo eliminado = cabeza;
    cabeza = cabeza.siguiente;
    eliminado.siguiente = null;
    return eliminado.dato;
}

Python

def apilar(self, elemento):
    nuevo = Nodo(elemento)
    nuevo.siguiente = self._cabeza
    self._cabeza = nuevo

def desapilar(self):
    if self.esta_vacia():
        raise IndexError("pila vacia")
    eliminado = self._cabeza
    self._cabeza = self._cabeza.siguiente
    eliminado.siguiente = None
    return eliminado.dato

apilar es O(1) real porque nunca copia nada, ya que cada nodo se pide justo cuando se necesita. La pila sobre arreglo de la Unidad 2 solo daba O(1) amortizado.

La cola enlazada: por qué hace falta otro puntero

Sin un segundo puntero, cada encolar tendría que recorrer toda la cadena para encontrar el último nodo. Con ultimo guardado aparte, encolar deja de necesitar cualquier recorrido.

Encolar al final, desencolar del frente

desencolar sigue trabajando sobre la cabeza, con costo O(1) real. encolar trabaja sobre ultimo, también O(1) real, y cada operación toca su propio extremo sin invadir el del otro.

Cola enlazada en Java y en Python

Java

public void encolar(Object elemento) {
    Nodo nuevo = new Nodo(elemento);
    if (ultimo == null) cabeza = nuevo;
    else ultimo.siguiente = nuevo;
    ultimo = nuevo;
}
public Object desencolar() {
    if (estaVacia()) throw new
        IllegalStateException("cola vacia");
    Nodo eliminado = cabeza;
    cabeza = cabeza.siguiente;
    if (cabeza == null) ultimo = null;
    eliminado.siguiente = null;
    return eliminado.dato;
}

Python

def encolar(self, elemento):
    nuevo = Nodo(elemento)
    if self._ultimo is None:
        self._cabeza = nuevo
    else:
        self._ultimo.siguiente = nuevo
    self._ultimo = nuevo
def desencolar(self):
    if self.esta_vacia():
        raise IndexError("cola vacia")
    eliminado = self._cabeza
    self._cabeza = self._cabeza.siguiente
    if self._cabeza is None: self._ultimo = None
    eliminado.siguiente = None
    return eliminado.dato

El bug de la cola que se traga sus elementos

La línea if (cabeza == null) ultimo = null; no es una precaución de más. encolar decide con ultimo == null, así que sin esa línea el siguiente encolar se cuelga del nodo huérfano y cabeza se queda en null.

Tres formas de resolver el mismo contrato

Implementación apilar / encolar desapilar / desencolar Localidad de caché
Arreglo redimensionable (Unidad 2) O(1) amortizado O(1) buena, casillas contiguas
Lista enlazada con ultimo O(1) real O(1) pobre, nodos dispersos
Lista enlazada sin ultimo O(n) al encolar O(1) pobre, nodos dispersos

La tercera fila no es una opción real, porque degrada la operación más común de la cola a O(n) apenas la cadena crece. El puntero ultimo es lo que separa una cola utilizable de una que no lo es.

java.util.LinkedList, doblemente enlazada, ya implementa Deque. El Javadoc de ArrayDeque advierte que esa clase, respaldada por arreglo, probablemente es más rápida que LinkedList usada como cola; una razón práctica es la localidad de caché.

Caso de estudio: paréntesis balanceados con una pila

Cada símbolo de apertura se apila, y cada símbolo de cierre debe coincidir con la cima. Los analizadores de los compiladores usan una pila con la misma idea para revisar estructuras anidadas.

Código de balanceada

def balanceada(cadena):
    pila = Pila()
    pares = {')': '(', ']': '[', '}': '{'}
    for simbolo in cadena:
        if simbolo in '([{':
            pila.apilar(simbolo)
        elif simbolo in pares:
            if pila.esta_vacia() or pila.desapilar() != pares[simbolo]:
                return False
    return pila.esta_vacia()

El return pila.esta_vacia() final es tan importante como el ciclo, porque una cadena como "(a" nunca produce un cierre incorrecto. Su único problema es un símbolo que se queda sin cerrar.

Casos reales: fila de atención y cola de impresión

Encolar entra por el final y desencolar sale por el frente, el mismo orden que exige una fila de atención o una cola de impresión. Una Pila, en cambio, es la estructura correcta para deshacer en un editor, porque el último cambio hecho tiene que ser el primero en revertirse.

Bloque 3. Árboles binarios de búsqueda

Bloque 3

Cada nodo gana un segundo camino, izquierdo y derecho, y esa segunda referencia le permite al árbol mantenerse ordenado mientras guarda datos, sin ningún paso aparte de ordenamiento.

Vocabulario de un árbol

La raíz es el único nodo sin padre. Un nodo sin hijos es una hoja. El nivel de un nodo es su distancia a la raíz, y la altura del árbol es la distancia, en enlaces, entre la raíz y la hoja más lejana.

Qué hace binario de búsqueda a un árbol

En un árbol binario de búsqueda, todo valor del subárbol izquierdo de cada nodo es menor que ese nodo, y todo valor de su subárbol derecho es mayor. La regla se cumple en cada nodo, no solo en la raíz, así que basta una comparación por nivel para saber a qué lado bajar. En este árbol no se permiten valores repetidos, e insertar un dato que ya existe no cambia nada.

El nodo con dos caminos

El nodo de las listas guardaba un dato y una sola referencia, siguiente. El nodo del árbol, NodoArbol, guarda un dato y dos referencias, izquierdo y derecho, cada una vacía o apuntando a un subárbol completo.

NodoArbol en Java y en Python

Java

public class NodoArbol {
    int dato;
    NodoArbol izquierdo;
    NodoArbol derecho;

    public NodoArbol(int dato) {
        this.dato = dato;
        this.izquierdo = null;
        this.derecho = null;
    }
}

Python

class NodoArbol:
    def __init__(self, dato):
        self.dato = dato
        self.izquierdo = None
        self.derecho = None

El dato es int en vez de un tipo genérico, porque insertar y buscar necesitan comparar con < y >, y en Java eso exige Comparable. Python compara sin declarar nada aparte.

Insertar: bajar hasta el hueco correcto

El caso base es un subárbol vacío, y ahí cuelga el nodo nuevo. El caso recursivo compara el dato y desciende por la referencia que corresponda, hasta llegar a una referencia vacía.

Código de insertar

Java

public void insertar(int dato) {
    raiz = insertar(raiz, dato);
}

private NodoArbol insertar(
        NodoArbol nodo, int dato) {
    if (nodo == null) {
        return new NodoArbol(dato);
    }
    if (dato < nodo.dato) {
        nodo.izquierdo =
            insertar(nodo.izquierdo, dato);
    } else if (dato > nodo.dato) {
        nodo.derecho =
            insertar(nodo.derecho, dato);
    }
    return nodo;
}

Python

def insertar(self, dato):
    self.raiz = self._insertar(
        self.raiz, dato)

def _insertar(self, nodo, dato):
    if nodo is None:
        return NodoArbol(dato)
    if dato < nodo.dato:
        nodo.izquierdo = self._insertar(
            nodo.izquierdo, dato)
    elif dato > nodo.dato:
        nodo.derecho = self._insertar(
            nodo.derecho, dato)
    return nodo

Buscar: el mismo camino que insertar

buscar baja exactamente por el mismo camino que seguiría insertar para ese valor. La única diferencia está en lo que pasa al llegar a una referencia vacía, porque insertar cuelga ahí un nodo y buscar concluye que el valor no está.

Caso de uso: el índice de un diccionario

Un autocompletar o el índice de una aplicación de diccionario necesitan responder rápido si una palabra está y qué hay cerca de ella. Un ABB resuelve las dos cosas con el mismo recorrido de comparaciones.

Con un millón de palabras en un árbol balanceado, la altura ronda veinte, porque log2 de un millón es 19.9. Encontrar una palabra o descartarla toma unas veinte comparaciones. Si el árbol degenera a una cadena, la misma consulta puede recorrer el millón completo sin que su código cambie.

20 comparaciones en un millón de nodos con altura logarítmica

1000000 comparaciones en el peor caso si ese millón degenera a una cadena

Los tres recorridos del mismo árbol

Inorden: ordenar gratis

El invariante del ABB garantiza que el subárbol izquierdo tiene todo lo menor y el derecho todo lo mayor. Inorden visita izquierda, nodo, derecha, así que el resultado siempre sale ordenado de menor a mayor, sin ningún paso adicional de ordenamiento.

def inorden(self):
    resultado = []
    self._inorden(self.raiz, resultado)
    return resultado

def _inorden(self, nodo, resultado):
    if nodo is None:
        return
    self._inorden(nodo.izquierdo, resultado)
    resultado.append(nodo.dato)
    self._inorden(nodo.derecho, resultado)

Recorrido por niveles con una cola

Cada nodo que sale del frente de la cola encola a sus hijos al final, primero el izquierdo y después el derecho. Así, un nivel completo sale antes de que empiece el siguiente.

Código del recorrido por niveles

def por_niveles(self):
    resultado = []
    if self.raiz is None:
        return resultado
    cola = Cola()
    cola.encolar(self.raiz)
    while not cola.esta_vacia():
        actual = cola.desencolar()
        resultado.append(actual.dato)
        if actual.izquierdo is not None:
            cola.encolar(actual.izquierdo)
        if actual.derecho is not None:
            cola.encolar(actual.derecho)
    return resultado

La Cola es la misma lista enlazada con cabeza y ultimo de las colas enlazadas, ahora guardando referencias a nodos del árbol en vez de datos sueltos. Cada nodo entra y sale una sola vez, así que el recorrido completo cuesta O(n).

Eliminar: los casos simples

Sin hijos, basta con quitar la referencia del padre. Con un solo hijo, ese hijo sube directo al lugar del nodo eliminado. Ninguno de los dos casos exige tocar el resto del árbol.

Eliminar un nodo con dos hijos

Con dos hijos, ninguno puede subir sin romper el orden. El dato se reemplaza por el de su sucesor inorden, el mínimo del subárbol derecho, y después se elimina ese sucesor de su posición original. Es la misma solución de la implementación de referencia de Weiss.

Bloque 4. Árboles AVL y árboles 2-3

Bloque 4

Un árbol que se corrige solo con rotaciones, y otro que nunca llega a desbalancearse.

Qué es un árbol AVL

El árbol binario de búsqueda simple no controla su forma. Con datos ya ordenados cae a una cadena de altura n menos 1, y su búsqueda vuelve a costar O(n).

Un árbol AVL es un árbol binario de búsqueda en el que, para cada nodo, la altura de su subárbol derecho y la de su subárbol izquierdo nunca difieren en más de uno. Lleva el nombre de Georgy Adelson-Velsky y Evgenii Landis.

Esa diferencia se llama factor de balanceo y se calcula como la altura del subárbol derecho menos la del izquierdo. Un valor fuera de {-1, 0, 1} dispara una rotación.

El factor de balanceo en cada nodo

La altura de un subárbol vacío se define como -1 y la de una hoja como 0. Con esa convención, el factor de cualquier hoja siempre es 0, y el cálculo se hace nodo por nodo, no solo en la raíz.

La clase NodoAVL

Java

class NodoAVL {
    int dato;
    NodoAVL izquierdo;
    NodoAVL derecho;
    int altura;
    NodoAVL(int dato) { this.dato = dato; }
}

int factor(NodoAVL n) {
    return altura(n.derecho)
         - altura(n.izquierdo);
}

Python

class NodoAVL:
    def __init__(self, dato):
        self.dato = dato
        self.izquierdo = None
        self.derecho = None
        self.altura = 0

def _factor(self, nodo):
    return (self._altura(nodo.derecho)
        - self._altura(nodo.izquierdo))

NodoAVL agrega un solo campo frente al NodoArbol del árbol binario simple, altura. Con la altura de los dos hijos a la mano, el factor de balanceo es una resta.

Caso izquierda-izquierda (LL)

NodoAVL rotarDerecha(NodoAVL nodo) {
    NodoAVL nueva = nodo.izquierdo;
    nodo.izquierdo = nueva.derecho;
    nueva.derecho = nodo;
    actualizarAltura(nodo);
    actualizarAltura(nueva);
    return nueva;
}

Caso derecha-derecha (RR)

NodoAVL rotarIzquierda(NodoAVL nodo) {
    NodoAVL nueva = nodo.derecho;
    nodo.derecho = nueva.izquierdo;
    nueva.izquierdo = nodo;
    actualizarAltura(nodo);
    actualizarAltura(nueva);
    return nueva;
}

Caso izquierda-derecha (LR)

El exceso viene en zigzag, el hijo derecho del hijo izquierdo. Una sola rotación a la derecha no lo arregla. Primero una rotación a la izquierda sobre el hijo izquierdo endereza el zigzag, y después la rotación a la derecha sobre el nodo original termina el balanceo.

Caso derecha-izquierda (RL)

Es el caso simétrico del anterior, porque el exceso viene del hijo izquierdo del hijo derecho. La corrección es la misma idea reflejada, con primero una rotación a la derecha sobre el hijo derecho y después una rotación a la izquierda sobre el nodo original.

Cuando se aplica la rotación equivocada

Aplicar rotarDerecha(30) sola donde el caso era zigzag deja a 10 como raíz, con 30 colgando a la derecha y 20 como hijo izquierdo de 30. El factor de 10 termina en 2, todavía fuera de {-1, 0, 1}. Una rotación simple solo endereza una línea recta, así que un zigzag primero necesita convertirse en línea recta.

Insertar con rebalanceo

Java

NodoAVL insertar(NodoAVL n, int d) {
    if (n == null) return new NodoAVL(d);
    if (d < n.dato)
        n.izquierdo = insertar(n.izquierdo, d);
    else if (d > n.dato)
        n.derecho = insertar(n.derecho, d);
    return balancear(n);
}

Python

def _insertar(self, n, d):
    if n is None:
        return NodoAVL(d)
    if d < n.dato:
        n.izquierdo = self._insertar(n.izquierdo, d)
    elif d > n.dato:
        n.derecho = self._insertar(n.derecho, d)
    return self._balancear(n)

La recursión es idéntica a la del árbol binario simple, salvo return balancear(n) en la vuelta de cada nivel. balancear actualiza la altura y, si el factor sale de {-1, 0, 1}, mira el factor del hijo más alto. Con el mismo signo basta una rotación simple, LL o RR; con signo contrario hace falta la doble, LR o RL.

Árboles 2-3: nodo de 2 y nodo de 3

Un nodo de 2 guarda un valor y tiene hasta dos hijos, igual que un nodo del árbol binario simple. Un nodo de 3 guarda dos valores ordenados y tiene hasta tres hijos, uno por cada rango que separan esas dos claves.

Insertar: división y propagación hacia arriba

Si la hoja de destino ya tenía dos claves, la clave del medio sube al padre y las otras dos quedan como dos nodos nuevos. Si el padre también se desborda, el mismo proceso se repite un nivel más arriba, hasta la raíz si hace falta.

El árbol 2-3 sobre el caso que degeneró al ABB

Insertar 10, 20, 30, 40, 50, 60 y 70 ya ordenados, el mismo orden ascendente que degenera un árbol binario simple a una cadena, deja aquí un árbol de altura 2 con sus cuatro hojas exactamente a la misma profundidad.

Bloque 5. Grafos

Bloque 5

La estructura más general del curso, sin raíz ni jerarquía, con cualquier nodo conectado con cualquier otro.

Qué es un grafo

Un grafo es un par G = (V, E), donde V es un conjunto de vértices y E es un conjunto de aristas, cada una conectando dos vértices de V. No hay raíz ni jerarquía de padre a hijo.

Dirigido y ponderado: dos preguntas que cambian el modelo

Una calle de un solo sentido es un grafo dirigido; una amistad recíproca es no dirigida. Un mapa de rutas suele ser dirigido y ponderado, con distancia o tiempo como peso, y las dependencias entre tareas forman un grafo dirigido en el que ninguna tarea termina dependiendo de sí misma.

Representar un grafo en memoria

La matriz de adyacencia guarda una casilla por cada par de vértices, exista o no la arista. La lista de adyacencia guarda, para cada vértice, solo sus vecinos reales.

Complejidad de las dos representaciones

Operación Matriz de adyacencia Lista de adyacencia
Espacio total O(V^2), siempre O(V + E)
Verificar arista (u, v) O(1) O(grado(u))
Recorrer vecinos de u O(V) O(grado(u))
Recorrer todas las aristas O(V^2) O(V + E)

Con cien mil vértices y trescientas mil aristas, un grado promedio de seis, la matriz pide V al cuadrado, diez mil millones de casillas. La lista pide 2E, seiscientas mil entradas, una por cada extremo de cada arista.

Cuándo conviene cada representación

La red de vuelos entre los aeropuertos de un país es dispersa, porque casi ningún par tiene vuelo directo, y le conviene la lista de adyacencia. En un grafo de doce vértices con más de la mitad de los pares conectados, la matriz no pesa y verifica una arista en O(1).

def agregar_arista(self, origen, destino):
    self.agregar_vertice(origen)
    self.agregar_vertice(destino)
    self.lista_adyacencia[origen].append(destino)
    self.lista_adyacencia[destino].append(origen)

def vecinos(self, v):
    return self.lista_adyacencia.get(v, [])

Cada arista se guarda dos veces, una por cada extremo, porque el grafo es no dirigido y el mismo enlace sirve para ir de origen a destino y de destino a origen.

DFS: bajar hasta el fondo antes de retroceder

La búsqueda en profundidad avanza por un vecino sin visitar hasta que no queda ninguno, y solo entonces retrocede. El conjunto de visitados evita que un ciclo la deje dando vueltas, y por eso el 3 que entró dos veces a la pila se descarta la segunda vez que sale.

DFS: versión recursiva y versión iterativa

Recursiva

def dfs(self, inicio):
    visitados = set()
    resultado = []
    self._dfs(inicio, visitados, resultado)
    return resultado

def _dfs(self, actual, visitados, resultado):
    visitados.add(actual)
    resultado.append(actual)
    for vecino in self.vecinos(actual):
        if vecino not in visitados:
            self._dfs(vecino, visitados, resultado)

Iterativa, con pila

def dfs_iterativo(self, inicio):
    resultado = []
    visitados = set()
    pila = [inicio]
    while pila:
        actual = pila.pop()
        if actual in visitados: continue
        visitados.add(actual)
        resultado.append(actual)
        for v in reversed(self.vecinos(actual)):
            if v not in visitados: pila.append(v)
    return resultado

BFS: nivel por nivel, con la Cola del curso

BFS visita todo lo que está a un salto antes de avanzar al siguiente nivel, y ese orden por distancia lo garantiza la Cola, que atiende primero lo que entró primero. Marcar visitado al entrar a la Cola evita encolar dos veces el mismo vértice.

BFS con la Cola

def bfs(self, inicio):
    resultado = []
    visitados = {inicio}
    cola = Cola()
    cola.encolar(inicio)
    while not cola.esta_vacia():
        actual = cola.desencolar()
        resultado.append(actual)
        for vecino in self.vecinos(actual):
            if vecino not in visitados:
                visitados.add(vecino)
                cola.encolar(vecino)
    return resultado

Mismo esqueleto que DFS iterativo. La diferencia central es una Cola en vez de una pila, y además BFS marca al encolar y no necesita reversed.

Saber si dos usuarios de una red social están unidos por alguna cadena de contactos, o si dos computadores de una red pueden enviarse un paquete, es preguntar si están en la misma componente conexa.

def componentes_conexas(self):
    componentes = []

Complejidades de esta unidad, en una tabla

Estructura Acceso por posición Búsqueda Inserción Eliminación

El promedio del ABB supone datos en orden aleatorio, con una altura esperada logarítmica aunque no balanceada. Con datos ya ordenados cae al peor caso, justo lo que las rotaciones del AVL y las divisiones del 2-3 evitan. En los grafos con lista de adyacencia, DFS y BFS cuestan O(V + E).

Lo que conecta toda la unidad

  • Una estructura dinámica pide memoria nodo por nodo, mientras el programa corre, no de una sola vez
  • El nodo repite la misma pieza en toda la unidad: un dato y una o más referencias a otros nodos
  • Insertar en la cabeza de una lista enlazada es O(1); insertar al final sin un puntero aparte es O(n)
  • Reasignar los punteros de un nodo en el orden equivocado puede romper la cadena completa
  • Pila y cola sobre lista enlazada cumplen el mismo contrato que sobre arreglo, con otro costo real
  • Un árbol binario de búsqueda ordena mientras almacena: cada nodo cumple el invariante con toda su descendencia
  • El recorrido inorden de un árbol binario de búsqueda entrega los datos ordenados de menor a mayor
  • Insertar datos ya ordenados en un árbol binario de búsqueda lo degrada a una cadena de altura n menos 1
  • El factor de balanceo de un nodo AVL y la división de un nodo 2-3 son dos formas distintas de evitar esa degradación
  • Un grafo deja atrás la jerarquía: cualquier nodo se conecta con cualquier otro, sin padre ni hijo
  • DFS con pila y BFS con cola recorren el mismo grafo con garantías distintas

Estructuras dinámicas: el resumen en una idea

Listas

Una referencia al siguiente nodo: insertar en la cabeza en O(1), sin ningún desplazamiento.

Árboles

Dos referencias y un invariante de orden: búsqueda en O(log n) mientras la altura siga controlada.

Grafos

Referencias sin jerarquía: DFS y BFS recorren cualquier red en O(V + E).

Una estructura dinámica cambia la posición fija de la memoria por una referencia explícita entre nodos, y ese cambio es exactamente lo que le permite crecer, ordenarse o enlazarse de formas que un arreglo nunca podría.

Lo que sigue

Dijkstra

El camino más barato desde un vértice hacia todos los demás, con pesos no negativos.

Prim

Árbol de expansión mínima que crece desde un vértice, arista más barata por arista más barata.

Kruskal

Árbol de expansión mínima que ordena todas las aristas por peso y evita cerrar ciclos.

La Unidad 4 retoma la misma clase GrafoPonderado y le agrega estos tres algoritmos, con el mismo vocabulario de nodo, enlace y recorrido, ahora sobre un grafo donde cada arista tiene un costo.
