1 Las muñecas que se abren en cascada

Piensa en una matrioska. La abres y adentro hay una muñeca igual, más pequeña. La abres también, y adentro hay otra. Repites la misma acción, abrir y mirar adentro, hasta que llegas a una muñeca sólida que no se abre porque no tiene nada dentro.

Ese momento en el que ya no hay nada más que abrir es el caso base: la única razón por la que la cascada de aperturas se detiene. Cada apertura anterior es el caso recursivo: la misma acción, aplicada a una versión más pequeña del mismo problema. Y hay un detalle que se te va a olvidar si no lo anotas ahora: mientras abres, vas dejando las cáscaras vacías apiladas una encima de la otra, en el orden en que las abriste. Para volver a armar la matrioska completa, las cierras en el orden contrario: primero la más pequeña, al final la más grande. Eso es exactamente lo que hace una función recursiva con la memoria del programa: apila un marco por cada llamada, y los deshace en el orden inverso al que los creó.

2 Caso base y caso recursivo

Toda función recursiva bien escrita tiene dos partes:

  • Caso base. La condición más simple del problema, la que se resuelve sin volver a llamar a la función. Es la muñeca sólida.
  • Caso recursivo. La función se llama a sí misma con una entrada más pequeña o más cercana al caso base, y combina ese resultado con el trabajo del paso actual.

El Tema 1 definió la finitud como una de las cinco propiedades que Knuth le exige a un algoritmo: terminar después de un número finito de pasos. Una función recursiva sin caso base, o con un caso base al que nunca se llega, deja de ser un algoritmo en sentido estricto. Cumple las otras cuatro propiedades sin problema y aun así no es un algoritmo, porque no termina.

3 Cómo se apila cada llamada

Cada vez que se invoca una función, el sistema reserva un espacio para esa invocación: un marco de pila (stack frame) que guarda sus parámetros, sus variables locales y el punto exacto al que debe volver cuando termine. Ese espacio no se comparte entre llamadas. Aunque el código escriba n en todas las invocaciones, cada marco tiene su propia copia.

Sigamos ese apilamiento con un ejemplo concreto: factorial(4). La función multiplica n por el resultado de factorial(n - 1), hasta llegar al caso base factorial(0) = 1. Cada llamada entra antes de que la anterior sepa su resultado, así que la pila crece hasta cuatro niveles antes de que se resuelva la primera multiplicación.

Fíjate en el orden de la columna “Sale”: el primer marco que devuelve un valor es el último que entró, factorial(0). Es la misma regla de la clase Pila que el Tema 2 te preparó para modelar: el último que entra es el primero que sale. La pila de llamadas del sistema no es una metáfora, es una estructura de datos real que tu programa nunca declara pero siempre usa.

4 Trazado en Python y en Java

La misma función, con una línea de rastro antes y después de la llamada recursiva, deja ver el crecimiento y el deshacer de la pila en la consola. Esta es la versión en Python, y la salida que produjo al ejecutarla en la máquina donde preparé este material:

def factorial(n):
    print(f"entra factorial({n})")
    if n == 0:
        print("caso base: factorial(0) = 1")
        return 1
    resultado = n * factorial(n - 1)
    print(f"sale factorial({n}) = {resultado}")
    return resultado

print("resultado final:", factorial(4))
entra factorial(4)
entra factorial(3)
entra factorial(2)
entra factorial(1)
entra factorial(0)
caso base: factorial(0) = 1
sale factorial(1) = 1
sale factorial(2) = 2
sale factorial(3) = 6
sale factorial(4) = 24
resultado final: 24

Las cinco líneas “entra” son la pila creciendo, la línea del caso base es el fondo de la pila, y las cuatro líneas “sale” son la pila deshaciéndose en orden inverso: exactamente lo que dibuja el diagrama de arriba. La misma lógica en Java, letra por letra, produce la misma secuencia:

public class Factorial {
    public static int factorial(int n) {
        System.out.println("entra factorial(" + n + ")");
        if (n == 0) {
            System.out.println("caso base: factorial(0) = 1");
            return 1;
        }
        int resultado = n * factorial(n - 1);
        System.out.println("sale factorial(" + n + ") = " + resultado);
        return resultado;
    }

    public static void main(String[] args) {
        System.out.println("resultado final: " + factorial(4));
    }
}

Compílalo y ejecútalo. Java no imprime nada distinto porque el mecanismo es el mismo: un marco por llamada, en una pila que administra la máquina virtual en vez del sistema operativo directamente.

5 Cuando falta el caso base: desbordamiento de pila

La pila de llamadas no crece para siempre. El espacio que el sistema le reserva a cada hilo de ejecución es finito, así que una función recursiva sin caso base, o con un caso base que nunca se alcanza, agota ese espacio y el programa termina en un error.

Java lo documenta en el Javadoc de StackOverflowError, subclase de Error que la máquina virtual lanza cuando se agota la memoria del hilo: “Thrown when a stack overflow occurs because an application recurses too deeply”. No hay un contador que avise antes: el programa corre hasta que la memoria real de la pila se acaba, y ese límite depende de cómo esté configurado el hilo.

Python resuelve el mismo riesgo distinto: en vez de esperar a que la pila de C que hay debajo se desborde y haga caer el intérprete entero, cuenta la profundidad de las llamadas y corta antes. La documentación de sys.getrecursionlimit() lo dice así: “Return the current value of the recursion limit, the maximum depth of the Python interpreter stack. This limit prevents infinite recursion from causing an overflow of the C stack and crashing Python.” Cuando se llega a ese límite, se lanza RecursionError, que la documentación describe como derivado de RuntimeError y que se lanza “when the interpreter detects that the maximum recursion depth … is exceeded”. Esta es la salida real de intentar una función sin caso base en la máquina donde preparé este material:

def sin_caso_base(n):
    return n * sin_caso_base(n - 1)

sin_caso_base(5)
RecursionError: maximum recursion depth exceeded

En esa misma máquina, con Python 3.13.4, sys.getrecursionlimit() devolvió 1000: por defecto el intérprete permite alrededor de mil llamadas apiladas antes de rendirse. Es un número de fábrica, ajustable con sys.setrecursionlimit(), y la propia documentación advierte que subirlo demasiado puede terminar igual, en una caída del intérprete en vez de un error controlado.

La conexión con el Tema 1 es directa: una recursión sin caso base no cumple la finitud que Knuth le exige a un algoritmo. RecursionError y StackOverflowError no son fallas del lenguaje, son la forma en que Python y Java te avisan que escribiste algo que, en sentido estricto, no era un algoritmo.

TipReto. Dibuja la pila antes de correr el código

Sin computador, en papel, dibuja los marcos de pila que se crean al llamar a esta función con suma(5):

def suma(n):
    if n == 0:
        return 0
    return n + suma(n - 1)
  1. Dibuja un rectángulo por cada llamada, de abajo hacia arriba, con el valor de n que le toca.
  2. Marca cuál es el caso base.
  3. Junto a cada rectángulo escribe el valor que ese marco va a devolver, empezando por el caso base y subiendo hasta la llamada original.
  4. Solo después de terminar el dibujo, copia la función en Python o en Java, ejecútala con suma(5) y compara el resultado final con lo que predijiste.
