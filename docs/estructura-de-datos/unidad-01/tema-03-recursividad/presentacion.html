Apilar y desapilar, donde el último que entra es el primero que sale: esa disciplina ya está funcionando por debajo de cualquier programa, lo uses explícitamente o no.

Las muñecas que se abren en cascada

Abrir y mirar adentro es el caso recursivo. La muñeca sólida, la que ya no se abre, es el caso base: la única razón por la que la cascada se detiene.

Caso base y caso recursivo

Caso base

La condición más simple del problema. Se resuelve sin volver a llamar a la función.

Caso recursivo

La función se llama a sí misma con una entrada más pequeña, y combina ese resultado con el trabajo del paso actual.

Un algoritmo debe cumplir finitud: termina después de un número finito de pasos. Una función recursiva sin caso base, o con uno al que nunca se llega, deja de ser un algoritmo en sentido estricto.

Qué guarda un marco de pila

Parámetros, variables locales y dirección de retorno. Ese tercer dato es el que le dice al programa adónde volver cuando la llamada termine.

La pila de llamadas para factorial(4)

Trazado en vivo: factorial en Python

Código

def factorial(n):
    print(f"entra factorial({n})")
    if n == 0:
        return 1
    r = n * factorial(n - 1)
    print(f"sale factorial({n}) = {r}")
    return r

Salida real

entra factorial(4)
entra factorial(3)
entra factorial(2)
entra factorial(1)
entra factorial(0)
sale factorial(1) = 1
sale factorial(2) = 2
sale factorial(3) = 6
sale factorial(4) = 24

El orden de las líneas “sale” es el inverso exacto del orden de las líneas “entra”.

La misma lógica en Java

public static int factorial(int n) {
    System.out.println("entra factorial(" + n + ")");
    if (n == 0) return 1;
    int r = n * factorial(n - 1);
    System.out.println("sale factorial(" + n + ") = " + r);
    return r;
}

Java no imprime nada distinto: un marco por llamada, en una pila que administra la máquina virtual en vez del sistema operativo directamente.

Recursión directa e indirecta

Código: es_par y es_impar

Código

def es_par(n):
    if n == 0:
        return True
    return es_impar(n - 1)

def es_impar(n):
    if n == 0:
        return False
    return es_par(n - 1)

Recursión directa frente a indirecta

Fibonacci: la recursión se ramifica

Código de fibonacci

def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

Una sola línea, dos llamadas recursivas. Las dos tienen que terminar antes de que la suma se pueda calcular.

Llamadas contra profundidad de la pila

n Llamadas totales Profundidad máxima
5 15 4
10 177 9
20 21.891 19
30 2.692.537 29

Las llamadas crecen exponencial y la profundidad crece lineal. Por eso fibonacci(30) tarda mucho sin nunca desbordar la pila: el problema no es la memoria, es el tiempo.

Recursión versus iteración

Iteración Recursión
Repetición Estructura repetitiva (bucle) Llamadas repetidas a la función
Condición de parada Condición del bucle Caso base
Costo en tiempo Sin llamadas adicionales Tiempo extra por cada llamada
Costo en memoria Una sola copia de las variables Un marco de pila por llamada activa

Si una solución iterativa es igual de clara, conviene preferirla: es más rápida y usa menos memoria. La recursión gana cuando el problema es naturalmente recursivo, como recorrer un árbol.

Cómo medir recursión y bucles en Python

import time, tracemalloc

def suma_recursiva(n):
    if n == 0:
        return 0
    return n + suma_recursiva(n - 1)

def suma_iterativa(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total

tracemalloc.start()
t0 = time.perf_counter()
suma_recursiva(900)
t1 = time.perf_counter()
_, pico = tracemalloc.get_traced_memory()
tracemalloc.stop()

Salida real, n = 900

recursiva:
  4047.6 microsegundos
  pico: 20640 bytes
iterativa:
  710.7 microsegundos
  pico: 144 bytes

La recursiva tardó 5.7 veces más y usó 143 veces más memoria rastreada. El tiempo varía entre ejecuciones; la memoria es estable, porque cada llamada reserva un marco de pila nuevo que la iterativa nunca crea.

Recorrer una lista con recursión

Código de suma_lista

def suma_lista(datos):
    if len(datos) == 0:
        return 0
    return datos[0] + suma_lista(datos[1:])

El caso base es la lista vacía. El caso recursivo separa la cabeza y se la suma al resto, una lista más corta y más cerca del caso base.

Cuando falta el caso base: desbordamiento

StackOverflowError (Java)

Error que lanza la máquina virtual cuando se agota la memoria reservada para la pila de un hilo. Sin aviso previo: corre hasta que la pila real se llena.

RecursionError (Python)

Excepción que el intérprete lanza al superar sys.getrecursionlimit() (cerca de 1000 por defecto). Corta antes de que la pila de C se desborde.

Tres condiciones para que la recursión termine

Un test que decide detener o continuar, una llamada recursiva que acerca al caso base, y un caso final que efectivamente detiene la cadena. Así se ven las tres en tres funciones ya conocidas:

Función 1. Test (caso base) 2. Llamada recursiva 3. Caso final
factorial(n) n == 0 n * factorial(n - 1) return 1
suma_lista(datos) len(datos) == 0 datos[0] + suma_lista(datos[1:]) return 0
es_par(n) n == 0 es_impar(n - 1) return True

Sin las tres, la recursión no cumple la finitud que exige todo algoritmo. fibonacci sin caso base, o suma_lista sin lista vacía, no terminarían nunca.
