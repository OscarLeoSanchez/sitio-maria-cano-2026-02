La pregunta de hoy

Por qué dos programas que resuelven exactamente el mismo problema pueden costar cincuenta mil veces más el uno que el otro.

No por el lenguaje. No por el computador.

Por cómo guardaron los datos y por el algoritmo con el que los recorren.

La tienda de la esquina

Doña Marta vende cuarenta productos y tiene dos sitios donde guardarlos.

  • El estante numerado. Cuarenta casillas seguidas, cada producto en la suya. El arroz está en la 12: camina hasta la 12 y estira el brazo.
  • La bodega del fondo. Cajas apiladas donde quepan, cada una con una nota pegada que dice cuál es la siguiente.

Vamos a volver a la tienda tres veces.

Qué es un algoritmo

Knuth, The Art of Computer Programming, volumen 1, 1968.

Las tres exigencias que se olvidan

  • Definición precisa. Una receta que dice “sal al gusto” no es un algoritmo: dos personas ejecutan el mismo paso de forma distinta.
  • Finitud. Un ciclo que espera una condición que nunca se cumple no termina.
  • Efectividad. Cada paso debe poder hacerse a mano, con papel y lápiz. “Encuentra el camino más corto” no cumple: ese paso es un algoritmo entero por dentro.

Cuando un programa se cuelga, la pregunta útil es cuál de las cinco se rompió.

El estante y la bodega tienen nombre

Leer contra insertar

Arreglo

Un bloque contiguo, pedido de una vez.

La dirección del elemento i se calcula: base más i por el tamaño.

Da igual si i es 3 o 999.999.

Lista enlazada

Memoria pedida nodo por nodo, cuando hace falta.

Cada nodo guarda la dirección del siguiente.

Para llegar al nodo 500.000 hay que caminar 500.000 nodos.

Lo que dice la documentación

Javadoc de ArrayList de Java 17:

“The size, isEmpty, get, set, iterator, and listIterator operations run in constant time. The add operation runs in amortized constant time, that is, adding n elements requires O(n) time.”

Javadoc de LinkedList: es una lista doblemente enlazada y las operaciones que indexan recorren la lista desde el extremo más cercano al índice pedido.

La trampa del list de Python

El list de Python es un arreglo dinámico, no una lista enlazada, aunque el nombre diga otra cosa.

Del wiki de complejidad temporal de Python:

  • append cuesta tiempo constante amortizado
  • el acceso por índice es constante
  • insert al inicio y pop(0) cuestan tiempo lineal, porque desplazan todos los elementos

datos.pop(0) dentro de un ciclo es un programa cuadrático sin que se note.

Un millón contra veinte

La binaria exige datos ordenados. La secuencial no exige nada.

La medición real

Elementos:            1000000
Busqueda secuencial:  1000000 comparaciones   34.4 ms
Busqueda binaria:     20 comparaciones   0.0171 ms
Version de Python:    3.13.4

Máquina: AMD Ryzen 5 4600H, 16 GB de RAM, Windows 11, Python 3.13.4.

Los milisegundos cambian de máquina a máquina. El número de comparaciones no cambia en ninguna.

El corazón del script

def binaria(datos, objetivo):
    pasos = 0
    izq, der = 0, len(datos) - 1
    while izq <= der:
        pasos += 1
        medio = (izq + der) // 2
        if datos[medio] == objetivo:
            return pasos
        if datos[medio] < objetivo:
            izq = medio + 1
        else:
            der = medio - 1
    return pasos

El script completo, con la secuencial y los cronómetros, está en la guía de la semana.

Contrato contra implementación

Liskov y Zilles, 1974: describir un tipo de dato por su comportamiento, es decir por su dominio, sus operaciones y sus restricciones, sin decir cómo se guarda en memoria.

  • Tipo de dato abstracto: el contrato
  • Estructura de datos: la organización en memoria que lo cumple

Un contrato admite varias implementaciones, y el código que lo usa no se entera de cuál eligieron.

Pila y cola

Pila

apilar, desapilar, cima, está vacía

El último que entra sale primero.

Deshacer en un editor. Llamadas recursivas pendientes.

Cola

encolar, desencolar, frente, está vacía

El primero que entra sale primero.

Trabajos de una impresora. Mensajes de un servidor.

Las dos se montan sobre un arreglo (Unidad 2) o sobre una lista (Unidad 3).

La escalera de crecimiento

n log2 n n n por log2 n n al cuadrado
1.000 unos 9,97 1.000 unos 9.966 1.000.000
1.000.000 unos 19,93 1.000.000 unos 19.930.000 1.000.000.000.000

Con mil elementos, el cuadrático hace cerca de 100 veces más trabajo que el de n log n. Con un millón, cerca de 50.000 veces más.

Por eso un programa que anda bien con la base de prueba se muere con la de producción.

2011: el peor caso a propósito

Klink y Walde, Chaos Communication Congress, diciembre de 2011.

  • Una tabla hash promedia tiempo constante para buscar
  • Su peor caso, cuando todas las llaves caen en el mismo sitio, es lineal
  • Un atacante envía parámetros que colisionan a propósito y agota la CPU del servidor
  • Aviso oCERT-2011-003, registrado como CVE-2011-4885
  • Impacto confirmado en PHP, ASP.NET y Java, entre otras plataformas

La estructura que eliges es también una decisión de seguridad.
