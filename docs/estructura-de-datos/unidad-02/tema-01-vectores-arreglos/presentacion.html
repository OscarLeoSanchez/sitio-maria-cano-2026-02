Conceptos previos

Qué es la notación O

La notación O describe cómo crece el trabajo de un algoritmo a medida que crece la cantidad de datos, sin depender de qué tan rápida sea la máquina donde corre.

Para qué sirve

Compara dos soluciones de forma objetiva, según cómo escalan, no según cuántos milisegundos tardó una ejecución en un equipo concreto.

Cómo se lee

O(algo) responde una pregunta: si n (la cantidad de datos) se duplica, ¿el trabajo se queda igual, se duplica también, o crece mucho más rápido?

Complejidades relevantes para este tema

Notación Qué significa Ejemplo
O(1), constante El trabajo no cambia sin importar cuántos datos haya Leer a[5]
O(n), lineal El trabajo crece en proporción directa a la cantidad de datos Recorrer o desplazar un arreglo completo

Con 10 elementos, O(1) sigue siendo 1 operación y O(n) son 10. Con 1000 elementos, O(1) sigue siendo 1 y O(n) son 1000: el trabajo de O(n) crece al mismo ritmo que los datos.

Comparación de crecimiento: O(1) frente a O(n)

Esta relación, el trabajo de O(n) escala en proporción directa al tamaño de la entrada mientras O(1) no depende de él, es la base para justificar la complejidad de cada operación presentada a continuación.

Qué es una excepción

Una excepción es la señal que un programa lanza en tiempo de ejecución cuando algo sale mal, en vez de seguir con un resultado incorrecto o fallar en silencio.

Java y Python tienen su propio mecanismo, con nombres distintos para representar el mismo tipo de problema. Este tema cubre dos de ellos.

Excepciones relevantes para este tema

Excepción Lenguaje Cuándo aparece
ArrayIndexOutOfBoundsException Java Acceder a un índice fuera del rango del arreglo
IndexError Python Acceder a una posición fuera del rango de la lista

Qué es un arreglo

Un arreglo es un bloque de memoria contiguo que guarda un número fijo de elementos del mismo tipo, cada uno accesible por un número de posición llamado índice, que empieza en 0.

Memoria contigua y la ecuación de acceso

  • La dirección de una casilla se calcula con la ecuación direccion = base + indice * tamaño_elemento, sin recorrer las casillas anteriores.

Los tres términos de la ecuación

direccion = base + indice * tamaño_elemento

base

La dirección de memoria donde empieza el arreglo completo, la casilla de índice 0.

índice

La posición que se pide, contando siempre desde 0.

tamaño_elemento

Cuántos bytes ocupa cada dato del tipo declarado, siempre el mismo en todo el arreglo.

Herramientas para medir en la práctica

Antes de seguir, conviene tener tres funciones simples que permitan comprobar en código lo explicado hasta ahora: cuánto tarda una operación, cuántos bytes pesa un dato, y en qué dirección de memoria vive cada posición de un arreglo.

Tiempo

Cuánto tarda una operación en ejecutarse.

Memoria

Cuántos bytes ocupa un dato.

Dirección

En qué posición exacta de memoria vive cada elemento.

Medir tiempo de ejecución

Java

public static long medirTiempoNanos(Runnable tarea) {
    long inicio = System.nanoTime();
    tarea.run();
    long fin = System.nanoTime();
    return fin - inicio;
}

Python

import time

def medir_tiempo(funcion, *args):
    inicio = time.perf_counter()
    resultado = funcion(*args)
    fin = time.perf_counter()
    return resultado, fin - inicio

System.nanoTime() y time.perf_counter() son parte de la biblioteca estándar de cada lenguaje, no hay que instalar nada. Ambos miden tiempo transcurrido con un reloj de alta precisión, no la fecha y hora del sistema, que es lo correcto para comparar el costo de una operación.

Medir el tamaño en memoria de un elemento

import sys

def medir_memoria(elemento):
    return sys.getsizeof(elemento)

sys es parte de la biblioteca estándar de Python. getsizeof devuelve los bytes que ocupa el objeto en sí, sin contar los objetos a los que hace referencia.

public static long memoriaUsadaAprox() {
    Runtime rt = Runtime.getRuntime();
    return rt.totalMemory() - rt.freeMemory();
}

Java no trae una función equivalente a sizeof. Esto solo aproxima la memoria total usada en el heap en ese instante, no el peso de un objeto puntual, y varía según cuándo pasó el recolector de basura. Medir el tamaño exacto de un objeto requiere una herramienta especializada, como la librería Java Object Layout (JOL), fuera del alcance de este curso.

Ver la dirección de memoria de cada posición

Una lista de Python guarda referencias, no valores, así que no sirve para ver direcciones que crezcan de forma predecible. Para eso hace falta un arreglo de datos crudos y contiguos, como los que ofrece NumPy.

NumPy es una librería externa, no viene incluida con Python, muy usada para trabajar con arreglos numéricos. Se usa aquí por una sola razón: a diferencia de una lista, guarda los valores uno junto al otro en memoria, igual que el modelo de arreglo de esta unidad.

import numpy as np

def direccion_elemento(arreglo, indice):
    return arreglo.ctypes.data + indice * arreglo.itemsize

Comprobando la ecuación con código real

arreglo = np.array([10, 20, 30, 40, 50], dtype=np.int32)
for i in range(len(arreglo)):
    print(i, direccion_elemento(arreglo, i))
0 140712834937920
1 140712834937924
2 140712834937928
3 140712834937932
4 140712834937936

Cada dirección aumenta exactamente itemsize bytes respecto a la anterior, 4 bytes para int32: la evidencia real de la ecuación direccion = base + indice * tamaño_elemento. Los números exactos cambian en cada ejecución y en cada equipo; lo que no cambia es el salto constante entre casillas consecutivas.

Y en Java?

Java no permite leer la dirección de memoria real de un objeto. El lenguaje la oculta a propósito, porque el recolector de basura puede mover los objetos de lugar en cualquier momento sin avisar al programa.

int idHash = System.identityHashCode(objeto);

identityHashCode entrega un número casi siempre distinto por objeto, y en algunas implementaciones se calcula a partir de la dirección real en el momento de la llamada, pero la especificación del lenguaje no lo garantiza ni promete que sea estable si el objeto se mueve. Nunca debe tratarse como una dirección de memoria real.

Ejercicio 1. Verificar la ecuación de acceso

  1. Crea un arreglo NumPy de al menos 10 enteros de 32 bits (dtype=np.int32).
  2. Usa direccion_elemento para calcular la dirección de cada índice.
  3. Compara cada resultado con arreglo[i:i+1].ctypes.data, la dirección real que entrega NumPy para ese mismo índice.
  4. Confirma que las dos coinciden siempre, y que la diferencia entre direcciones consecutivas es igual a itemsize.

Ejercicio 2. Comprobar que el acceso es O(1)

  1. Crea un arreglo o lista con varios millones de elementos.
  2. Usa medir_tiempo (o medirTiempoNanos) para medir el acceso al índice 0.
  3. Mide también el acceso al último índice.
  4. Compara los dos tiempos: deberían ser prácticamente iguales, sin importar la posición consultada.

Tamaño en bytes de tamaño_elemento, según el tipo

En Java, cada tipo primitivo tiene un tamaño fijo, definido en la especificación del lenguaje (JLS 4.2). Ese número es exactamente el tamaño_elemento de la ecuación anterior.

Tipo (Java) Bytes por elemento
byte 1
char 2
int 4
long 8
double 8

Un int[1000] pesa aproximadamente 1000 * 4 = 4000 bytes, más una pequeña cabecera fija del objeto arreglo. El peso total crece de forma lineal con la cantidad de elementos.

Arreglos de referencias frente a arreglos de valores

El tamaño de un arreglo de referencias no depende de qué tan largo sea cada objeto al que apunta: todas las casillas miden lo mismo, sea una sola letra o un párrafo completo.

Python: hasta un entero es un objeto

import sys
print(sys.getsizeof(42))            # 28
print(sys.getsizeof([1, 2, 3]))     # 88

En Python no hay tipos primitivos dentro de una lista: hasta el número 42 es un objeto completo de 28 bytes, con su propia cabecera. La lista de 3 elementos solo guarda 3 referencias; los objetos enteros viven aparte, igual que los String en el ejemplo de Java.

Declarar un arreglo

Java

int[] numeros = new int[5];
// JLS 4.12.5: se llena con ceros

Python

numeros = [10, 20, 30]

Java reserva el tamaño desde el inicio y lo rellena con el valor por defecto del tipo. Python crea la lista ya con sus valores.

Comportamiento fuera de los límites del arreglo

int[] numeros = {10, 20, 30};
System.out.println(numeros[5]);
// ArrayIndexOutOfBoundsException
numeros = [10, 20, 30]
print(numeros[5])
# IndexError: list index out of range

Ninguno de los dos falla en silencio: ambos avisan de inmediato con una de las excepciones presentadas anteriormente.

Recorrer un arreglo

Ciclo indexado

Repite mientras un contador i va de 0 hasta el tamaño; en cada vuelta accede a a[i].

Ciclo por cada elemento

Entrega directamente cada valor, uno por uno, sin exponer el índice.

for (int i = 0; i < numeros.length; i++) {
    System.out.println(numeros[i]);
}
for (int n : numeros) {
    System.out.println(n);
}
for i in range(len(numeros)):
    print(numeros[i])
for n in numeros:
    print(n)

O(1) acceder a una casilla

O(n) recorrer el arreglo completo

Insertar en el medio, paso a paso

numeros = [10, 20, 30, 40]
numeros.insert(2, 25)

Insertar o eliminar en el inicio o en el medio cuesta O(n) porque cada elemento desde el punto de inserción hasta el final se mueve una posición.

Eliminar del medio, paso a paso

numeros = [10, 20, 30, 40]
numeros.pop(1)  # quita y devuelve el 20

pop(indice) quita el elemento de esa posición y devuelve su valor. Sin argumento, quita el último.

Complejidad de un arreglo, operación por operación

Operación Complejidad Por qué
Acceder o leer a[i] O(1) multiplicación y suma
Modificar a[i] = x O(1) misma dirección de siempre
Insertar o eliminar al final O(1) amortizado sin desplazamiento, si hay espacio
Insertar o eliminar al inicio o en medio O(n) desplaza todo lo posterior
Buscar por valor O(n) recorrido casilla por casilla

Arreglos de Java: tamaño fijo

En Java, un arreglo tiene tamaño fijo desde que se crea. No existe una operación para agregarle una casilla más: crecer significa crear un arreglo distinto y copiar.

int[] original = {10, 20, 30};
int[] masGrande = Arrays.copyOf(original, 6);
// masGrande = [10, 20, 30, 0, 0, 0]

Crecer significa crear uno nuevo y copiar, un costo O(n) cada vez que se agota el espacio.

Capacidad y tamaño: dos ideas distintas

tamaño

Cuántos elementos hay usados de verdad. Es lo que devuelve len() en Python.

capacidad

Cuánto espacio hay reservado en memoria, usado o no. No es visible directamente, pero existe por debajo.

Cuando una estructura dinámica se queda sin capacidad, no reserva una casilla más: reserva de golpe un bloque más grande, para no repetir esa operación costosa demasiado seguido.

Listas de Python: arreglos dinámicos internamente

La documentación de CPython lo describe así: son arreglos de longitud variable, no listas enlazadas. Por debajo hay un bloque contiguo con espacio de sobra.

Qué hace append()

append(valor) agrega valor justo después del último elemento usado, sin desplazar nada. Si sobra capacidad, cuesta O(1).

lista = []
for i in range(20):
    lista.append(i)
    print(id(lista))
# el id() no cambia: el buffer interno se reemplaza por dentro

Capacidad reservada al crecer una lista

Fuente de la secuencia real: el código de listobject.c de CPython. La proporción de crecimiento tiende a 1,125 veces el tamaño anterior, no al doble.

ArrayList de OpenJDK crece cerca de 1,5 veces, pero eso no es parte del contrato público del Javadoc: solo promete O(1) amortizado, el factor exacto es un detalle de implementación.

Caso de estudio: complejidad de una cola simulada con lista

pop(0) quita y devuelve el primer elemento de la lista, desplazando todo lo demás una posición hacia el inicio.

tareas = []
tareas.append(nueva_tarea)      # O(1) amortizado, nada se mueve
siguiente = tareas.pop(0)       # O(n), todo se recorre y se desplaza

Repetir pop(0) en un ciclo cuesta O(n al cuadrado) en total, aunque cada línea se vea inocente. La documentación de collections.deque advierte justo contra usar una lista como cola por esta razón.

Caso de estudio: ausencia de verificación de límites (C)

int id_sequence[3];
id_sequence[3] = 456;  /* escritura fuera de los limites */

Esta clase de error, CWE-787, ocupó el primer lugar del Top 25 de MITRE en 2023. La excepción que lanzan Java y Python evita esta categoría completa de fallas por diseño.

Reto 1

  1. Un ciclo llama a lista.insert(0, i) exactamente n veces, empezando de una lista vacía.
  2. Cada insert(0, ...) cuesta O(n) porque desplaza todo lo que ya está.
  3. ¿Cuál es la complejidad total del ciclo completo?

Reto 2

int[] datos = {10, 20, 30, 40};
for (int i = 0; i <= datos.length; i++) {
    System.out.println(datos[i]);
}
  1. Ejecuta mentalmente el ciclo para datos.length == 4.
  2. ¿En qué valor de i ocurre el problema, y qué excepción lanza?

Resumen

  • Qué es un arreglo, por qué es contiguo, y cómo se calcula la dirección de un índice
  • Por qué acceder a a[i] es O(1) y por qué insertar o eliminar en medio es O(n)
  • Por qué un arreglo Java no puede crecer, y qué hace Arrays.copyOf para simular que crece
  • Por qué una lista de Python es, por dentro, un arreglo dinámico con capacidad y tamaño distintos
  • Por qué usar pop(0) para simular una cola con una lista es un antipatrón documentado oficialmente, y qué complejidad produce en un ciclo
  • Por qué la verificación de límites de Java y Python evita una categoría entera de errores graves
