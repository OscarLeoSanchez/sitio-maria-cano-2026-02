Análisis experimental del rendimiento de un arreglo y selección de estructura

Autor/a

Oscar Leonel Sánchez Conde

Fecha de publicación

24 de septiembre de 2026

Unidad Unidad 2. Estructuras fijas
Tema Tema 1. Vectores o arreglos
Modalidad Trabajo en parejas, 2 horas
Lenguaje Java o Python, a elección de la pareja

Una aplicación debe administrar hasta un millón de registros numéricos. Su tarea es determinar, con evidencia experimental propia, qué operaciones son adecuadas sobre un arreglo y cuáles generan problemas de rendimiento, y recomendar con argumentos técnicos qué estructura conviene en dos escenarios de uso distintos.

1 Propósito

Contrastar la teoría del Tema 1 con mediciones reales. Usted va a predecir el costo de cada operación sobre un arreglo, medirlo en su propio equipo, explicar las diferencias entre lo que esperaba y lo que obtuvo, y tomar una decisión de diseño sustentada en sus propios datos.

La actividad no evalúa cuánto código escribe. Evalúa la calidad del análisis: que cada número tenga su origen, que cada complejidad venga acompañada de lo que ocurre en memoria, y que cada decisión esté justificada con las mediciones.

2 Reglas

  • Trabajo en parejas. Los dos integrantes deben poder explicar cualquier parte del reporte.
  • No está permitido usar asistentes de inteligencia artificial en ninguna forma durante la actividad.
  • Fuentes permitidas para investigar: la guía del Tema 1, la documentación oficial de Python, el Javadoc de Java y la especificación del lenguaje Java (JLS). Todo dato tomado de una fuente se cita en el reporte con el nombre de la fuente.
  • El reporte se escribe a mano en una hoja, con los nombres de los dos integrantes, en el orden de las fases y sobre la marcha. No se pasa en limpio al final.
  • Cada número del reporte lleva la operación de la que salió. Cada complejidad O(…) lleva la explicación de qué se mueve por dentro.

3 El problema

La aplicación realiza con frecuencia estas ocho operaciones sobre el conjunto de registros:

  1. Acceso por posición.
  2. Actualización de una posición.
  3. Búsqueda de un valor.
  4. Recorrido completo.
  5. Inserción al final.
  6. Inserción al inicio.
  7. Inserción en una posición intermedia.
  8. Eliminación al inicio.

La estructura de partida es un arreglo: int[] o ArrayList en Java, list en Python.

5 Fase 2. Medición

La actividad incluye un programa base que mide el tiempo de una operación sobre conjuntos de 1 000, 10 000, 100 000 y 1 000 000 de elementos. Trae una sola operación implementada. Complételo con las siete restantes y ejecútelo.

Cómo medir correctamente cada operación es parte del trabajo. Tenga en cuenta, por ejemplo, que una inserción al inicio repetida un millón de veces puede tardar minutos, así que conviene repetirla un número fijo de veces por tamaño, y que la búsqueda debe ser de un valor que no está en el conjunto, para que recorra todo.

Programa base en Python

import time

TAMANOS = [1_000, 10_000, 100_000, 1_000_000]
REPETICIONES = 100


def medir(nombre, preparar, operacion):
    """Mide una operacion sobre cada tamano y muestra el tiempo promedio por repeticion."""
    for n in TAMANOS:
        datos = preparar(n)
        inicio = time.perf_counter()
        for _ in range(REPETICIONES):
            operacion(datos, n)
        fin = time.perf_counter()
        promedio = (fin - inicio) / REPETICIONES
        print(f"{nombre:24} n={n:>9}  {promedio:.9f} s")
    print()


def lista_de(n):
    return list(range(n))


# Operacion de ejemplo: acceso por posicion
medir("acceso por posicion", lista_de, lambda datos, n: datos[n - 1])

Programa base en Java

import java.util.ArrayList;
import java.util.List;
import java.util.function.BiConsumer;
import java.util.function.IntFunction;

public class Benchmark {

    static final int[] TAMANOS = {1_000, 10_000, 100_000, 1_000_000};
    static final int REPETICIONES = 100;

    static void medir(String nombre, IntFunction<List<Integer>> preparar,
                      BiConsumer<List<Integer>, Integer> operacion) {
        for (int n : TAMANOS) {
            List<Integer> datos = preparar.apply(n);
            long inicio = System.nanoTime();
            for (int r = 0; r < REPETICIONES; r++) {
                operacion.accept(datos, n);
            }
            long fin = System.nanoTime();
            double promedio = (fin - inicio) / 1e9 / REPETICIONES;
            System.out.printf("%-24s n=%9d  %.9f s%n", nombre, n, promedio);
        }
        System.out.println();
    }

    static List<Integer> listaDe(int n) {
        List<Integer> lista = new ArrayList<>(n);
        for (int i = 0; i < n; i++) lista.add(i);
        return lista;
    }

    public static void main(String[] args) {
        // Operacion de ejemplo: acceso por posicion
        medir("acceso por posicion", Benchmark::listaDe, (datos, n) -> datos.get(n - 1));

    }
}

6 Fase 3. Contraste entre teoría y experimento

Con la tabla completa, calcule los cocientes de crecimiento: para cada operación, cuántas veces creció el tiempo cuando n pasó de 1 000 a 10 000, de 10 000 a 100 000 y de 100 000 a 1 000 000. Con esos cocientes responda en la hoja:

Con eso explique, con sus propias palabras, qué significa que una operación sea O(1) amortizado.
