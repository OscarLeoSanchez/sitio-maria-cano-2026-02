Unidad Unidad 4. Métodos de ordenamiento, búsqueda y eficiencia
Tema Tema 1. Algoritmos de ordenamiento

La Unidad 3 cerró con GrafoPonderado, una estructura donde cada arista guarda un costo y donde quedó abierta la pregunta de cuál camino resulta más barato entre dos vértices. Antes de resolver esa pregunta con Dijkstra, Prim y Kruskal más adelante en esta unidad, hace falta resolver una pregunta más elemental que aparece en casi cualquier programa real, cómo poner en orden una colección de datos. Este tema retoma el arreglo de la Unidad 2, la estructura de memoria contigua donde acceder a un índice cuesta O(1), y estudia seis formas distintas de reorganizar sus elementos de menor a mayor: burbuja, inserción, selección, quicksort, shellsort y radix. Los seis trabajan sobre el mismo arreglo de siete números a lo largo de toda la guía, así que cada diagrama parte del mismo punto y permite comparar visualmente cómo cada algoritmo llega al mismo resultado final por un mecanismo distinto. El Tema 2 retoma estos mismos seis algoritmos para formalizar con notación Big-O por qué unos crecen mucho más rápido que otros a medida que el arreglo se agranda, así que las mediciones de hoy son el material sobre el que trabaja esa formalización.

1 El arreglo de ejemplo

Los seis algoritmos ordenan el mismo arreglo de partida, [64, 25, 12, 22, 11, 90, 34], para que las siete casillas de cada diagrama representen siempre los mismos siete números y el estudiante pueda comparar un algoritmo contra otro sin tener que reconstruir mentalmente un arreglo distinto cada vez.

Ordenar significa reorganizar esos siete valores para que queden en orden no decreciente, [11, 12, 22, 25, 34, 64, 90], sin perder ni duplicar ninguno. Los seis algoritmos llegan a ese mismo resultado, pero difieren en tres preguntas que vas a responder para cada uno: cuántas comparaciones y movimientos hace en el mejor, el promedio y el peor de los casos, si conserva el orden relativo de dos elementos iguales, lo que se llama ser estable, y si necesita memoria extra proporcional al tamaño del arreglo o le basta con un puñado de variables, lo que se llama ordenar en el lugar, o in-place.

2 Burbuja: comparar vecinos y burbujear el mayor hacia el final

El algoritmo de burbuja, o bubble sort, recorre el arreglo comparando cada pareja de elementos vecinos, y los intercambia si están en el orden incorrecto. Tras una pasada completa, el elemento más grande de todo el arreglo terminó desplazándose, comparación tras comparación, hasta la última posición, exactamente como una burbuja que sube hasta la superficie. Repetir esa pasada n menos uno veces garantiza que el arreglo completo quede ordenado, porque cada pasada nueva fija en su lugar final al menos un elemento más.

public static void burbuja(int[] a) {
    int n = a.length;
    for (int i = 0; i < n - 1; i++) {
        boolean intercambio = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (a[j] > a[j + 1]) {
                int temp = a[j];
                a[j] = a[j + 1];
                a[j + 1] = temp;
                intercambio = true;
            }
        }
        if (!intercambio) {
            break;
        }
    }
}
def burbuja(a):
    n = len(a)
    for i in range(n - 1):
        intercambio = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                intercambio = True
        if not intercambio:
            break

La bandera intercambio es lo que separa una burbuja bien escrita de una que siempre corre sus n menos uno pasadas completas sin importar el arreglo de entrada. Si una pasada entera no encuentra ninguna pareja fuera de orden, el arreglo ya está ordenado y seguir intentando es trabajo perdido, como muestra la pasada 5 del diagrama, que confirma el orden sin mover nada. Esa bandera es también la que explica por qué burbuja nunca intercambia dos elementos iguales entre sí, la condición a[j] > a[j + 1] usa estrictamente mayor que, así que dos valores iguales quedan donde estaban uno respecto al otro, lo que hace que burbuja sea estable.

3 Inserción: construir el prefijo ordenado uno a uno

El algoritmo de inserción, o insertion sort, mantiene un prefijo del arreglo ya ordenado, que empieza siendo solo el primer elemento, y toma el siguiente elemento sin ordenar, la clave, para insertarlo en la posición que le corresponde dentro de ese prefijo, desplazando a la derecha a todo lo que sea mayor que ella. Funciona porque el prefijo a[0..i-1] es un invariante que se cumple antes de procesar cada índice i, ya está ordenado, y la inserción de a[i] en su lugar exacto extiende ese invariante un elemento más, hasta que el prefijo cubre el arreglo completo.

public static void insercion(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int clave = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > clave) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = clave;
    }
}
def insercion(a):
    for i in range(1, len(a)):
        clave = a[i]
        j = i - 1
        while j >= 0 and a[j] > clave:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = clave

Fíjate en i=5 del diagrama, insertar 90 no desplaza ningún elemento del prefijo, porque 90 ya es mayor que 64, el último elemento del prefijo, y el ciclo while termina en la primera comparación. Ese es el mejor caso de una inserción individual, O(1). En cambio, i=4, insertar 11, desplaza los cuatro elementos del prefijo completo, porque 11 es menor que todos ellos, el peor caso de una inserción individual, O(n). Igual que burbuja, la condición a[j] > clave usa estrictamente mayor que, así que dos valores iguales nunca intercambian su orden relativo, lo que hace que inserción sea estable.

4 Selección: elegir el mínimo en cada pasada

El algoritmo de selección, o selection sort, recorre la parte sin ordenar del arreglo buscando su elemento mínimo, y lo intercambia con el primer elemento de esa parte sin ordenar. Tras esa pasada, el prefijo ordenado creció un elemento, igual que en inserción, pero el mecanismo es el opuesto, inserción trae el siguiente elemento hacia el prefijo ya ordenado, selección trae el mínimo del resto hacia el borde del prefijo. El invariante es que a[0..i-1] contiene siempre los i elementos más pequeños del arreglo, ya ordenados, antes de procesar la posición i.

public static void seleccion(int[] a) {
    int n = a.length;
    for (int i = 0; i < n - 1; i++) {
        int minimo = i;
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[minimo]) {
                minimo = j;
            }
        }
        int temp = a[i];
        a[i] = a[minimo];
        a[minimo] = temp;
    }
}
def seleccion(a):
    n = len(a)
    for i in range(n - 1):
        minimo = i
        for j in range(i + 1, n):
            if a[j] < a[minimo]:
                minimo = j
        a[i], a[minimo] = a[minimo], a[i]

La pasada 4 del diagrama es la que más enseña de este algoritmo, el mínimo del resto, 25, ya estaba exactamente en la posición donde debía quedar, así que el intercambio a[i], a[minimo] = a[minimo], a[i] intercambia la posición 3 consigo misma, sin cambiar nada visible. Aun así, el ciclo interno recorrió las tres posiciones restantes completas para confirmar que 25 era el mínimo, porque selección no tiene ninguna forma de saber que el resto ya está ordenado sin revisarlo entero. Por eso selección hace siempre el mismo número de comparaciones sin importar si el arreglo de entrada ya viene ordenado o viene en el peor desorden posible, a diferencia de burbuja e inserción, que sí se adaptan a un arreglo casi ordenado. Ese intercambio que salta posiciones lejanas es también lo que rompe la estabilidad, mover un elemento igual a otro por encima de varias posiciones intermedias puede invertir el orden relativo que tenían dos elementos iguales al principio, así que selección no es estable en su forma clásica.

Mejor caso Caso promedio Peor caso Espacio extra Estable In-place
O(n^2), siempre recorre el resto completo para confirmar el minimo O(n^2) O(n^2) O(1) No Si

NotaSolución del Reto 3

La segunda es correcta. El ciclo interno de seleccion siempre recorre n - 1 - i elementos en cada pasada i, sin ninguna condición que dependa del valor de esos elementos, así que la cantidad total de comparaciones, la suma de n - 1 más n - 2 hasta 1, es siempre la misma fórmula n(n-1)/2, sin importar si el arreglo llega ordenado, invertido o mezclado al azar. Esa es la diferencia central frente a burbuja, cuya bandera de intercambio le permite terminar en una sola pasada sobre un arreglo ya ordenado, y frente a inserción, cuyo ciclo while se detiene de inmediato cuando encuentra la posición correcta. Selección no tiene ningún mecanismo parecido, por lo que su complejidad de mejor caso es igual a la de peor caso, O(n^2) en los dos casos.

5 Quicksort: dividir alrededor de un pivote

Quicksort elige un elemento del arreglo, el pivote, y reorganiza el resto alrededor de él, de modo que todos los elementos menores o iguales queden a su izquierda y todos los mayores queden a su derecha, una operación que se llama partición. Al terminar esa partición, el pivote ya está en su posición final definitiva, y el problema se redujo a ordenar por separado las dos mitades, que no se mezclan entre sí. Ese es el patrón de divide y vencerás que ya viste en la Unidad 1, la partición es el paso de dividir y el paso de combinar es trivial, no hace falta fusionar nada porque las dos mitades quedan ordenadas exactamente donde tienen que quedar. Este tema usa el esquema de partición de Lomuto, que fija el pivote como el último elemento del segmento.

public static void quicksort(int[] a) {
    quicksort(a, 0, a.length - 1);
}

private static void quicksort(int[] a, int bajo, int alto) {
    if (bajo < alto) {
        int p = particion(a, bajo, alto);
        quicksort(a, bajo, p - 1);
        quicksort(a, p + 1, alto);
    }
}

private static int particion(int[] a, int bajo, int alto) {
    int pivote = a[alto];
    int i = bajo - 1;
    for (int j = bajo; j < alto; j++) {
        if (a[j] <= pivote) {
            i++;
            int temp = a[i];
            a[i] = a[j];
            a[j] = temp;
        }
    }
    int temp = a[i + 1];
    a[i + 1] = a[alto];
    a[alto] = temp;
    return i + 1;
}
def quicksort(a, bajo=0, alto=None):
    if alto is None:
        alto = len(a) - 1
    if bajo < alto:
        p = particion(a, bajo, alto)
        quicksort(a, bajo, p - 1)
        quicksort(a, p + 1, alto)


def particion(a, bajo, alto):
    pivote = a[alto]
    i = bajo - 1
    for j in range(bajo, alto):
        if a[j] <= pivote:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[alto] = a[alto], a[i + 1]
    return i + 1

El puntero i de particion marca el final del bloque de elementos ya confirmados como menores o iguales al pivote, y cada vez que a[j] cumple esa condición, i avanza y el elemento entra al bloque con un intercambio. Al final del ciclo, intercambiar a[i + 1] con el pivote lo deja exactamente en la frontera entre el bloque de menores y el de mayores, su posición final. Fíjate en la raíz del árbol del diagrama, el pivote 34 reparte el arreglo de forma razonable, cuatro elementos a la izquierda contra dos a la derecha, pero la partición izquierda vuelve a elegir el último elemento de su propio segmento como pivote, que resulta ser 11, el mínimo de ese segmento, y produce una división de cero elementos contra tres, la peor partición posible dentro de ese segmento. Ese mismo patrón, elegir por accidente el elemento más pequeño o más grande como pivote, es justo lo que degenera por completo el rendimiento de quicksort cuando el arreglo de entrada ya viene ordenado, como vas a medir más adelante en esta guía.

O(n log n), el pivote parte el segmento en dos mitades parejas en cada nivel O(n log n) O(n^2), el pivote resulta ser siempre el minimo o el maximo del segmento O(log n), la pila de llamadas recursivas No Si

La segunda es correcta. particion(0,3) toma como pivote a[3], que en ese segmento vale 11, el elemento más pequeño de los cuatro. 6 Shellsort: inserción con saltos que se acortan

Shellsort mejora a inserción atacando su punto más débil, que un elemento pequeño extraviado cerca del final del arreglo tiene que desplazarse una posición a la vez hasta llegar al principio. En vez de comparar solo elementos vecinos, shellsort compara elementos separados por una distancia, el salto o gap, y ordena cada uno de esos subconjuntos entrelazados con una inserción normal. Al terminar con un salto, repite el proceso con un salto más pequeño, hasta terminar con un salto de 1, que es una inserción común y corriente, pero aplicada sobre un arreglo que ya quedó casi ordenado por los saltos anteriores, así que esa última pasada es mucho más barata que una inserción sobre el arreglo original. Este tema genera la secuencia de saltos con la fórmula de Knuth, gap = gap * 3 + 1, que para siete elementos produce los saltos 4 y 1.

public static void shellsort(int[] a) {
    int n = a.length;
    int gap = 1;
    while (gap < n / 3) {
        gap = gap * 3 + 1;
    }
    while (gap >= 1) {
        for (int i = gap; i < n; i++) {
            int temp = a[i];
            int j = i;
            while (j >= gap && a[j - gap] > temp) {
                a[j] = a[j - gap];
                j -= gap;
            }
            a[j] = temp;
        }
        gap /= 3;
    }
}
def shellsort(a):
    n = len(a)
    gap = 1
    while gap < n // 3:
        gap = gap * 3 + 1
    while gap >= 1:
        for i in range(gap, n):
            temp = a[i]
            j = i
            while j >= gap and a[j - gap] > temp:
                a[j] = a[j - gap]
                j -= gap
            a[j] = temp
        gap //= 3

El código es literalmente el mismo bucle de insercion, con gap en vez de 1 como la distancia entre el elemento que se compara y el que se desplaza, así que shellsort no es un algoritmo distinto de inserción, es la misma idea aplicada primero a distancia y después de cerca. La subsecuencia A del diagrama, índices 0 y 4, con valores 64 y 11, se ordena sola en un solo intercambio, 11 pasa al índice 0 y 64 al índice 4, mientras que la pasada de gap=1 que sigue ya no tiene que mover ningún elemento a más de una posición de distancia, porque el trabajo pesado ya lo hizo el gap=4. La complejidad exacta de shellsort depende de qué secuencia de saltos se use, algo que no le pasa a ningún otro algoritmo de este tema, la secuencia original de Shell, dividir entre dos cada vez, degrada al peor caso a O(n^2), mientras que la secuencia de Knuth de este tema, y otras como la de Hibbard, acotan el peor caso en O(n elevado a 3/2), sin que exista todavía una demostración cerrada del caso promedio exacto para la mayoría de las secuencias conocidas. Igual que selección, un elemento puede saltar por encima de otro igual a él durante una pasada de salto largo, así que shellsort no es estable.

Mejor caso Caso promedio Peor caso Espacio extra Estable In-place
O(n log n), arreglo ya ordenado, cada pasada de salto no mueve nada depende de la secuencia de saltos, con Knuth entre O(n^{4/3}) y O(n^{3/2}) O(n^{3/2}) con la secuencia de Knuth, O(n^2) con la secuencia original de Shell O(1) No Si

NotaSolución del Reto 5

La segunda es correcta. La pasada final con gap=1 es, por sí sola, una inserción completa y correcta, capaz de ordenar cualquier arreglo sin ayuda de nada más, así que el resultado sigue siendo el arreglo ordenado. Lo que se pierde es el ahorro, sin las pasadas previas con saltos mayores, el elemento 11 tendría que recorrer las cuatro posiciones que lo separan de su lugar correcto una por una, exactamente el mismo trabajo que haría insercion sobre el arreglo original. El valor de shellsort está completo en esas pasadas previas, que mueven los elementos lejanos grandes distancias de una sola vez y dejan cada vez menos trabajo para la pasada final, no en un mecanismo distinto al de inserción.

7 Radix sort: ordenar sin comparar, dígito por dígito

Los cinco algoritmos anteriores deciden el orden comparando un elemento contra otro, a[j] > a[j+1], a[j] < a[minimo], a[j] <= pivote. Radix sort no compara ningún par de elementos entre sí, en cambio examina un dígito a la vez de cada número y los distribuye en diez baldes, uno por cada valor posible de dígito, del 0 al 9. Empieza por el dígito menos significativo, el de las unidades, y termina por el más significativo, reclasificando el arreglo completo en cada pasada. Esa variante, que procesa del dígito menos al más significativo, se llama LSD por las siglas en inglés de least significant digit.

public static void radix(int[] a) {
    int maximo = a[0];
    for (int v : a) {
        if (v > maximo) {
            maximo = v;
        }
    }
    for (int exp = 1; maximo / exp > 0; exp *= 10) {
        contarPorDigito(a, exp);
    }
}

private static void contarPorDigito(int[] a, int exp) {
    int n = a.length;
    int[] salida = new int[n];
    int[] conteo = new int[10];
    for (int i = 0; i < n; i++) {
        conteo[(a[i] / exp) % 10]++;
    }
    for (int d = 1; d < 10; d++) {
        conteo[d] += conteo[d - 1];
    }
    for (int i = n - 1; i >= 0; i--) {
        int digito = (a[i] / exp) % 10;
        salida[conteo[digito] - 1] = a[i];
        conteo[digito]--;
    }
    System.arraycopy(salida, 0, a, 0, n);
}
def radix(a):
    maximo = max(a)
    exp = 1
    while maximo // exp > 0:
        baldes = [[] for _ in range(10)]
        for num in a:
            digito = (num // exp) % 10
            baldes[digito].append(num)
        a[:] = [num for balde in baldes for num in balde]
        exp *= 10

Las dos versiones aplican la misma idea con una diferencia de estilo. La versión Python usa diez listas, una por cada balde, y agrega cada número a la lista de su dígito recorriendo el arreglo en orden, exactamente la técnica que se ve en el diagrama. La versión Java usa la técnica clásica de conteo con suma de prefijos, cuenta cuántos números caen en cada dígito, acumula esos conteos para saber en qué posición del arreglo de salida termina cada balde, y coloca cada número recorriendo el arreglo original de atrás hacia adelante para que los números con el mismo dígito conserven su orden relativo. Las dos técnicas cuestan lo mismo, O(n + b) por pasada, siendo b la base, diez en este caso, y las dos son estables, lo que resulta obligatorio para que radix sort funcione: la segunda pasada del diagrama solo produce el orden correcto porque 11 seguía apareciendo antes que 12 al entrar a esa pasada, un orden que la primera pasada por unidades ya había fijado y que una clasificación no estable podría haber roto sin ningún aviso. Aunque el código Python reasigna el mismo objeto lista con a[:] = ..., por dentro construye baldes auxiliares que ocupan espacio proporcional a n más la base en cada pasada, así que radix sort no ordena en el lugar según la definición que usa esta guía, la de un algoritmo que se las arregla con un número constante de celdas extra.

Mejor caso Caso promedio Peor caso Espacio extra Estable In-place
O(d(n+b)) O(d(n+b)) O(d(n+b)) O(n+b), los baldes auxiliares de cada pasada Si No

Ahí, d es el número de dígitos del valor máximo y b es la base, diez en el caso decimal. Con b fijo y d acotado, digamos números de a lo sumo diez dígitos, esa complejidad se comporta como O(n) para efectos prácticos, lineal en el tamaño del arreglo, algo que ningún algoritmo de los cinco anteriores puede prometer.

Por qué radix se sale de la cota O(n log n)

Todo algoritmo de ordenamiento que decide el orden final comparando pares de elementos, que es exactamente lo que hacen burbuja, inserción, selección, quicksort y shellsort, tiene un límite teórico probado, ningún algoritmo de ese tipo puede ordenar n elementos en menos de aproximadamente n log n comparaciones en el peor caso, sin importar qué tan ingenioso sea. Radix sort no choca contra ese límite porque no lo compite, en ningún momento de sus dos pasadas compara un número contra otro, solo pregunta qué dígito tiene cada número y lo coloca en el balde correspondiente, una operación de clasificación, no de comparación. Por eso puede terminar en tiempo proporcional a n para un rango de dígitos acotado, más rápido que la cota de n log n que sí limita a los otros cinco algoritmos de este tema. La demostración formal de esa cota, con el argumento del árbol de decisión y las n factorial ordenaciones posibles, es justamente el tema con el que arranca el Tema 2 de esta unidad, que retoma los seis algoritmos de hoy para formalizar con notación Big-O por qué cada uno crece como crece.

Al arreglo de ejemplo se le agrega un octavo número, 900, que tiene tres dígitos en vez de los dos que tienen los otros siete. Antes de seguir, decide cuántas pasadas necesita radix para ordenar el arreglo de ocho números.

NotaSolución del Reto 6

La segunda es correcta. El ciclo while maximo // exp > 0 en Python, y su equivalente maximo / exp > 0 en Java, sigue agregando pasadas mientras el número más grande, ahora 900, todavía tenga dígitos sin procesar en la posición exp, así que con maximo = 900 el ciclo corre para exp = 1, exp = 10 y exp = 100, tres pasadas en total. Para un número más corto, como 34, calcular (34 // 100) % 10 da cero, porque la división entera de 34 entre 100 es cero, así que 34 cae automáticamente en el balde 0 durante la pasada de las centenas, sin que el código necesite ningún caso especial ni ningún relleno explícito con ceros a la izquierda. La aritmética entera resuelve sola el problema de los números con menos dígitos.

8 Comparando los seis: un benchmark real

Con los seis algoritmos ya implementados, la pregunta que sigue es cuánto se nota en la práctica la diferencia entre O(n^2) y algo más cercano a O(n log n). El siguiente script en Python corre los cinco primeros algoritmos, más shellsort, sobre el mismo arreglo de tres mil números generados al azar, midiendo el tiempo de cada uno. La versión de quicksort usada aquí elige el pivote al azar en cada partición, en vez de tomar siempre el último elemento como en la sección anterior, por razones que la siguiente sección explica en detalle.

import random
import time


def burbuja(a):
    a = a[:]
    n = len(a)
    for i in range(n - 1):
        intercambio = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                intercambio = True
        if not intercambio:
            break
    return a


def seleccion(a):
    a = a[:]
    n = len(a)
    for i in range(n - 1):
        minimo = i
        for j in range(i + 1, n):
            if a[j] < a[minimo]:
                minimo = j
        a[i], a[minimo] = a[minimo], a[i]
    return a


def insercion(a):
    a = a[:]
    for i in range(1, len(a)):
        clave = a[i]
        j = i - 1
        while j >= 0 and a[j] > clave:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = clave
    return a


def quicksort_aleatorio(a):
    a = a[:]
    _quicksort(a, 0, len(a) - 1)
    return a


def _quicksort(a, bajo, alto):
    while bajo < alto:
        p = _particion(a, bajo, alto)
        if p - bajo < alto - p:
            _quicksort(a, bajo, p - 1)
            bajo = p + 1
        else:
            _quicksort(a, p + 1, alto)
            alto = p - 1


def _particion(a, bajo, alto):
    idx = random.randint(bajo, alto)
    a[idx], a[alto] = a[alto], a[idx]
    pivote = a[alto]
    i = bajo - 1
    for j in range(bajo, alto):
        if a[j] <= pivote:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[alto] = a[alto], a[i + 1]
    return i + 1


def shellsort(a):
    a = a[:]
    n = len(a)
    gap = 1
    while gap < n // 3:
        gap = gap * 3 + 1
    while gap >= 1:
        for i in range(gap, n):
            temp = a[i]
            j = i
            while j >= gap and a[j - gap] > temp:
                a[j] = a[j - gap]
                j -= gap
            a[j] = temp
        gap //= 3
    return a


random.seed(42)
N = 3000
datos = [random.randint(0, 1_000_000) for _ in range(N)]

algoritmos = [
    ("burbuja", burbuja),
    ("seleccion", seleccion),
    ("insercion", insercion),
    ("quicksort", quicksort_aleatorio),
    ("shellsort", shellsort),
]

print(f"N = {N} elementos aleatorios, mismo arreglo de entrada para los cinco")
tiempos = {}
for nombre, func in algoritmos:
    inicio = time.perf_counter()
    func(datos)
    tiempos[nombre] = time.perf_counter() - inicio
    print(f"{nombre:12s} {tiempos[nombre]:8.4f} s")

base = tiempos["quicksort"]
print("tiempo relativo contra quicksort (quicksort = 1.0x):")
for nombre, t in tiempos.items():
    print(f"{nombre:12s} {t / base:8.2f}x")

Shellsort quedó apenas un doce por ciento más lento que quicksort, muy por delante de los tres algoritmos O(n^2), confirmando en la práctica que su complejidad subcuadrática no es solo una promesa teórica. Nota que selección e inserción, aunque los dos son O(n^2), no tardan lo mismo, inserción se beneficia de que el arreglo generado al azar no está tan lejos del orden final como el peor caso posible, mientras que selección, como ya viste en el Reto 3, hace siempre el mismo trabajo sin importar la entrada.

9 Cuando quicksort falla: el pivote mal elegido

Quicksort promedio es rápido precisamente porque, en la mayoría de las entradas, un pivote elegido al azar cae cerca de la mediana del segmento y lo reparte en dos mitades parecidas. El Reto 4 ya mostró qué pasa cuando eso no ocurre, y el peor escenario posible para el esquema de este tema, con pivote igual al último elemento, es un arreglo que ya viene ordenado, cada partición elige como pivote al elemento más grande de lo que queda, deja todo el resto a un solo lado, y la recursión se convierte en una cadena de n particiones anidadas en vez de un árbol de altura log n. El siguiente script compara ese esquema fijo contra un esquema con pivote aleatorio, los dos sobre el mismo arreglo de mil quinientos números ya ordenados.

import random
import sys
import time

sys.setrecursionlimit(20000)
comparaciones = 0


def quicksort_pivote_fijo(a, bajo, alto):
    global comparaciones
    if bajo < alto:
        p = particion_pivote_fijo(a, bajo, alto)
        quicksort_pivote_fijo(a, bajo, p - 1)
        quicksort_pivote_fijo(a, p + 1, alto)


def particion_pivote_fijo(a, bajo, alto):
    global comparaciones
    pivote = a[alto]  # siempre el ultimo elemento, sin aleatorizar
    i = bajo - 1
    for j in range(bajo, alto):
        comparaciones += 1
        if a[j] <= pivote:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[alto] = a[alto], a[i + 1]
    return i + 1


def quicksort_pivote_aleatorio(a, bajo, alto):
    global comparaciones
    if bajo < alto:
        p = particion_pivote_aleatorio(a, bajo, alto)
        quicksort_pivote_aleatorio(a, bajo, p - 1)
        quicksort_pivote_aleatorio(a, p + 1, alto)


def particion_pivote_aleatorio(a, bajo, alto):
    global comparaciones
    idx = random.randint(bajo, alto)
    a[idx], a[alto] = a[alto], a[idx]
    pivote = a[alto]
    i = bajo - 1
    for j in range(bajo, alto):
        comparaciones += 1
        if a[j] <= pivote:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[alto] = a[alto], a[i + 1]
    return i + 1


N = 1500
arreglo_ordenado = list(range(N))

datos1 = arreglo_ordenado[:]
comparaciones = 0
inicio = time.perf_counter()
quicksort_pivote_fijo(datos1, 0, len(datos1) - 1)
tiempo_fijo = time.perf_counter() - inicio
comparaciones_fijo = comparaciones

datos2 = arreglo_ordenado[:]
comparaciones = 0
random.seed(7)
inicio = time.perf_counter()
quicksort_pivote_aleatorio(datos2, 0, len(datos2) - 1)
tiempo_aleatorio = time.perf_counter() - inicio
comparaciones_aleatorio = comparaciones

print(f"N = {N} elementos, arreglo ya ordenado de entrada para los dos casos")
print("quicksort con pivote fijo (ultimo elemento):")
print(f"  comparaciones: {comparaciones_fijo}")
print(f"  tiempo:        {tiempo_fijo:.4f} s")
print("quicksort con pivote aleatorio:")
print(f"  comparaciones: {comparaciones_aleatorio}")
print(f"  tiempo:        {tiempo_aleatorio:.4f} s")
n_cuadrado = N * (N - 1) // 2
print(f"referencia: N*(N-1)/2 = {n_cuadrado} (comparaciones de un O(n^2) puro)")

El número de comparaciones del pivote fijo, 1 124 250, coincide exactamente con la fórmula N(N-1)/2 del peor caso teórico de un algoritmo O(n^2) puro, no es una aproximación, es el mismo número. Cada partición sobre un arreglo ya ordenado con pivote igual al último elemento compara ese pivote contra todos los elementos que quedan, sin descartar ninguno, la misma cadena de particiones anidadas del Reto 4 pero llevada a mil quinientos elementos en vez de cuatro. El pivote aleatorio, sobre la misma entrada exacta, hizo sesenta y tres veces menos comparaciones y tardó una fracción del tiempo, porque elegir el pivote al azar hace que la probabilidad de repetir ese peor caso, aunque nunca sea cero, se vuelva insignificante en la práctica. Esta es la razón concreta por la que las implementaciones de quicksort de uso real, incluida la que corrió en el benchmark de la sección anterior, jamás fijan el pivote en una posición predecible del segmento.

Ningún algoritmo de esta tabla es universalmente el mejor. Burbuja e inserción, con su mejor caso lineal, sirven bien sobre datos casi ordenados, un registro al que se le agregan pocos elementos nuevos cada vez. Selección conviene cuando escribir en memoria es caro y leer es barato, porque hace como máximo n menos uno intercambios sin importar el tamaño del arreglo, contra los muchos más intercambios que puede hacer burbuja. Quicksort es, en la práctica, la opción por defecto para datos genéricos en memoria, siempre que el pivote se elija de forma aleatoria o con una técnica como la mediana de tres. Shellsort rinde bien cuando la memoria extra de otros algoritmos más rápidos no es aceptable, ordena en el lugar sin la recursión de quicksort. Radix sort gana cuando los datos tienen una cantidad acotada de dígitos, como identificadores numéricos o fechas, porque su costo no depende del logaritmo de n sino del número de dígitos, a costa de necesitar memoria auxiliar y de no servir directamente para comparar objetos generales, solo para claves que se puedan descomponer en dígitos o símbolos discretos.
