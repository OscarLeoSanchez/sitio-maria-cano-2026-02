La pregunta de la sesión

Qué tiene el teléfono que obliga a programar distinto, y cuáles son los tres caminos para construirle software.

Vienes de Lenguajes de programación para la web. El teléfono abre las mismas páginas que ya sabes escribir, y aun así hay cosas que solo te deja hacer si el usuario dice que sí.

Reto 1. Quién hace la pregunta

Abre el navegador de tu teléfono y entra a un sitio que use tu ubicación: un mapa, una tienda con sedes, el clima. El sitio lo escoges tú.

Cuando intente saber dónde estás, no toques nada y responde:

  1. Quién hace la pregunta
  2. Si la dirección dice http o https
  3. Cuántas opciones te da el aviso y en qué se diferencian

Qué acabó de pasar

El mecanismo

  • navigator.permissions.query()
  • Estado: granted, denied o prompt
  • El tercero produce el aviso

La condición

  • Solo en contexto seguro
  • Es decir, HTTPS

Dentro del aparato

Dos consecuencias

La memoria es fija

No hay ranuras. No puedes pedirle al usuario que agregue más, y el teléfono que compró hace tres años sigue con la que tenía.

La memoria es compartida

El sistema, tu aplicación y todas las demás sacan de la misma bolsa. El sistema tiene que poder recuperarle memoria a alguien.

Quién decide cuándo corre tu código

Tu código declara condiciones. El momento lo escoge el sistema operativo.

El sistema mira cuánta batería queda, si está conectado a la corriente, qué red hay y cuánto usa el dueño tu aplicación. Después decide si la tarea corre ahora o espera en la cola.

Android y Apple, la misma idea

Android

  • WorkManager agrupa tareas
  • RequiresCharging: no ejecuta salvo que el equipo esté cargando
  • El sistema limita la ubicación en segundo plano para ahorrar batería

Apple

  • Minimizar entrada y salida
  • Agrupar transacciones de red
  • Clases de calidad de servicio para priorizar
  • La red es uno de los mayores consumos de energía

Reto 2. El inventario de tu teléfono

En equipos, con un solo teléfono a la vista.

  1. Listen los sensores que creen que tiene, buscándolos por lo que el aparato hace
  2. Clasifiquen cada uno en movimiento, posición o ambiente
  3. Marquen cuáles podría leer una aplicación web abierta en ese teléfono
  4. Escojan uno que la web no alcanza y propongan cómo resolverlo sin él

Dos maneras de aislar una aplicación

Android

  • Todas las aplicaciones corren en el sandbox de aplicaciones
  • Cada una recibe un identificador de usuario único
  • Permisos normales, peligrosos y de firma

Una aplicación web

  • Vive dentro del sandbox del navegador
  • Sin identidad propia en el sistema
  • El permiso queda amarrado al origen, o sea al dominio

Por eso pregunta el navegador

Android instala la aplicación con identidad propia y la aísla a nivel de usuario. Una aplicación web solo tiene el origen desde el que se sirvió.

Cambia el dominio y el navegador vuelve a preguntar, porque guardó el permiso contra el origen anterior.

Progressive Web App: tres requisitos

  1. Manifiesto web app válido, con nombre, iconos y display: standalone
  2. Servicio por HTTPS
  3. Un service worker registrado, para funcionar sin conexión

Sin service worker el sitio puede ser instalable en algunos navegadores, pero no funciona sin conexión.

El service worker en el medio

Lo que iOS hace distinto

iOS e iPadOS 16.4 añadieron Web Push para aplicaciones web agregadas a la pantalla de inicio.

Las notificaciones no funcionan en una pestaña normal de Safari: hace falta que el usuario haya instalado antes la aplicación en la pantalla de inicio. Si tu producto depende de notificaciones, ese paso extra es parte del diseño.

Tres confusiones frecuentes

  1. Una aplicación web es más que una página que se ve bien en el teléfono. Hacen falta manifiesto, HTTPS y service worker.
  2. Responsivo no es adaptable. Responsivo reorganiza un mismo layout con media queries; adaptable sirve variantes distintas de interfaz.
  3. Una PWA no reemplaza a una nativa en cualquier escenario. El push en iOS y el acceso a sensores desde la web ponen el límite.

Angular y React, cómo se definen

Angular, en angular.dev

  • El framework de desarrollo web para construir aplicaciones modernas
  • Lo mantiene un equipo de Google
  • Basado en TypeScript
  • Arquitectura de componentes

React, en react.dev

  • La librería para interfaces de usuario web y nativas
  • Se llama librería, no framework
  • No prescribe enrutamiento ni obtención de datos
