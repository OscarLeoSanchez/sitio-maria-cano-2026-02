Dos formas de compilar el mismo código

Desarrollo: JIT

  • Compilador just in time
  • Corre en una VM de Dart en el dispositivo
  • Habilita el hot reload

Producción: AOT

  • Compilador ahead of time
  • Genera código máquina nativo ARM o x64
  • Corre sin máquina virtual

Mismo código Dart, dos destinos distintos según el momento del proyecto.

Todo es un widget

Cualquier cosa que veas en pantalla, incluido el espaciado, es un widget. Los widgets se organizan en el árbol de widgets.

  1. StatelessWidget: inmutable una vez construido
  2. StatefulWidget: mantiene un objeto State aparte que sí puede cambiar
  3. build(): describe cómo se ve el widget en este instante, y Flutter lo vuelve a llamar solo

El árbol de widgets del contador

setState avisa, build() redibuja

void _incrementarContador() {
  setState(() {
    _contador++;
  });
}

Sin setState, _contador cambiaría en memoria pero la pantalla seguiría mostrando el número viejo.

Hot reload: qué pasa exactamente

La app se construyó de verdad

  1. flutter create genera el proyecto base con el ejemplo de contador
  2. Se reescribió main.dart con nombres en español, misma estructura
  3. flutter analyze corrió sobre el proyecto real
  4. flutter build web compiló el proyecto a la plataforma web

flutter analyze, salida real

$ flutter analyze
Analyzing flutter_demo...
No issues found! (ran in 58.8s)

El tiempo exacto varía según el equipo. Lo que importa es “No issues found!”
