01

Qué pasa cuando tu app habla con internet

El clima de hoy no está en tu código. ¿Cómo llega hasta la pantalla del celular?

El problema

El catálogo necesita un dato de afuera

APIUn servicio que responde preguntas
Una API es un servicio en internet que responde preguntas con un formato fijo. Tú pides con una URL y te devuelve datos en JSON.
El menú de un restaurante: dice qué puedes pedir y cómo te lo entregan. No necesitas saber cómo se cocina.
Open-Meteo es una API del clima gratuita y sin llave: buena para practicar.
Pensar que la app "ya sabe" el dato. Cada vez que lo necesitas, lo vuelves a pedir.

La app conoce los productos. El clima de hoy en Envigado lo sabe otro computador.

¿Dónde vive el dato del clima de hoy?

Lo tiene un servidor de Open-Meteo, que lo actualiza cada 15 minutos. Tu app debe pedirlo cada vez: eso es una petición.

Modelo mental

Una petición sale, una respuesta vuelve

LatenciaEl tiempo del viaje
La latencia es lo que tarda el mensaje en ir y volver. Con wifi puede ser 100 ms; con señal débil, varios segundos.
Un domicilio: no depende de ti cuánto se demora la moto, pero sí qué haces mientras esperas.
Probar solo con buen wifi. En el celular de un comprador la red es lenta o se cae.

La dirección

Cada parte de la URL dice algo

ParámetrosLo que va después de ?
Los parámetros van después de ? como pares clave=valor separados por &. Le dicen al servidor qué quieres exactamente.
La ruta es el puesto del mercado; los parámetros son tu pedido: "de la mora, una libra".
Uri.https arma la URL por ti a partir de un mapa de parámetros:
Uri.https('api.open-meteo.com', '/v1/forecast', {
  'latitude': '6.17',
  'longitude': '-75.58',
  'current': 'temperature_2m',
});
Escribir un nombre de parámetro mal (current=temperatura): Open-Meteo responde 400.

El sello de la respuesta

Un número resume la respuesta

FamiliasEl primer dígito manda
El código de estado tiene tres dígitos. El primero dice la familia: 2 salió bien, 4 pediste algo mal, 5 falló el servidor.
El semáforo del pedido: verde (2xx), amarillo porque te equivocaste tú (4xx), rojo porque falló la cocina (5xx).
Usar el cuerpo sin mirar el código. Un 404 también trae cuerpo: un mensaje de error, no tus datos.

JSON desde cero

La respuesta llega como texto. ¿Cómo se convierte en datos que Dart entiende?

Modelo mental

JSON es texto con forma

JSONReglas de escritura
JSON es un formato de texto para datos. Tiene seis tipos de valor y reglas estrictas: claves entre comillas dobles, sin coma después del último elemento.
Un formulario impreso con casillas: cada casilla tiene un nombre y algo escrito adentro.
Usar comillas simples 'nombre'. JSON solo acepta comillas dobles.

De texto a datos

jsonDecode convierte el texto en un mapa

MapClaves y valores en Dart
Un Map guarda valores bajo una clave. Map<String, dynamic> significa: claves de texto y valores de cualquier tipo, porque el JSON mezcla números, textos y objetos.
datos['current']['temperature_2m'] abre el cajón current y dentro el cajón temperature_2m.
Escribir mal una clave: datos['Current'] devuelve null. Las claves distinguen mayúsculas.
final datos = jsonDecode(respuesta.body);
final actual = datos['current'];
final temperatura = actual['temperature_2m'];
print(temperatura); // 22.3

EstadoLa memoria de la pantalla
El estado es un dato que cambia mientras la app corre y que la pantalla debe mostrar. Si nunca cambia, no es estado.
El marcador de un partido: el número cambia y el tablero tiene que mostrar el nuevo.
Cantidad en la canasta, si está cargando, la temperatura que llegó.

Un StatelessWidget no cambia solo

StatelessWidgetDibuja con lo que recibe
Un StatelessWidget solo tiene build. Sus campos son final y no tiene forma de pedirle a Flutter "dibuja otra vez".

StatefulWidget

  • En la pantalla se lee Llevas 0, siempre: nadie pide dibujar otra vez y cuenta vuelve a 0 en cada build.

Modelo mental

Dos clases: el widget y su State

¿Por qué dos?Una se recrea, la otra vive
Flutter crea widgets nuevos muchas veces; son baratos y no cambian. El State se crea una vez y sobrevive a esas recreaciones: por eso los datos que cambian viven ahí.
El widget es el marco de la pizarra: se puede cambiar por otro igual. El State es lo escrito en la pizarra y se conserva, con sus anotaciones.
Guardar cuenta en la clase del widget: se pierde cada vez que Flutter lo recrea.

04

Asincronía mínima en Dart

La respuesta tarda. ¿Qué hace la app mientras tanto?

Modelo mental

Un Future es un valor que llegará después

FuturePendiente, con valor o con error
Un Future representa un resultado que todavía no está. Termina de una de dos formas: con un valor o con un error.
El número de pedido: aún no tienes el almuerzo, pero te llamarán cuando esté listo o si no se pudo.
Future<String>: llegará un String. Future<void>: llegará el aviso de "terminé", sin valor.
Tratar el Future como si ya fuera el dato: print(pedirSaludo()) imprime Instance of 'Future<String>'.
Future<String> pedirSaludo() async {
  await Future.delayed(const Duration(seconds: 2));
  return 'Hola desde el servidor';
}
Pides un almuerzo y te dan un número de pedido. El número es el Future: todavía no es la comida. Te sientas en tu mesa (eso es await) y cuando tu número está listo vas por ella.
Vida de un Future

Simulación

await espera sin congelar la pantalla

awaitPausa la función, no la app
await pausa solo la función donde está escrito. Mientras tanto Flutter sigue dibujando y atendiendo toques.
Pones el arroz y, mientras se cocina, lavas la loza. No te quedas mirando la olla.
Usar await en una función sin async: Dart no compila.

¿En qué orden salen los mensajes?

Future<void> cargar() async {
  print('1. Pido el saludo');

  print('3. Llegó: $saludo');

¿Qué orden ves en la consola?

cargar() imprime 1 y llega al await: ahí se pausa y le devuelve el control a main, que imprime 2. Dos segundos después llega el saludo y la función sigue con 3.

Errores

try intenta, catch atrapa

try / catchUn plan B para la red
Si algo dentro de try lanza un error, Dart salta de inmediato al catch. Las líneas que faltaban del try no se ejecutan.
Vas al mercado por mora (try). Si no hay, compras fresas (catch). No te quedas parado frente al puesto vacío.
No poner try: un error de red sin atrapar deja la pantalla cargando para siempre.
Future<void> cargar() async {
  try {
    final saludo = await pedirSaludo();
    print('Llegó: $saludo');
  } catch (e) {
    print('Falló: $e');
  }
}

Tiempo de espera y reintento

La señal es mala. ¿Cuánto debe esperar la app antes de rendirse y qué hace después?

Tiempo de espera

Ponle un límite a la espera

timeoutDejar de esperar
.timeout(duración) envuelve el Future: si no termina a tiempo, lanza TimeoutException. Viene de import 'dart:async';.
Esperar el bus: si en 20 minutos no pasa, tomas otra decisión.
Creer que el timeout cancela la petición. Solo deja de esperarla; si la respuesta llega tarde, se ignora.
final respuesta = await http
    .get(url)
    .timeout(const Duration(seconds: 5));
// ...
} on TimeoutException {
  mostrarError('La respuesta tardó demasiado.');
}
El paquete http no trae límite propio: lo pones tú. Cinco segundos es una decisión del equipo.

Reintento

Un botón Reintentar vuelve a llamar a cargar

¿Cuándo sirve?No todo error se arregla reintentando
Reintentar sirve cuando la falla es pasajera: sin señal, tiempo agotado, 500 o 503. Con 400 o 404 la URL está mal y reintentar da el mismo resultado.
Si el bus no pasó, esperas el siguiente. Si estás en el paradero equivocado, esperar no sirve.

Simulación

La lluvia decide qué se sugiere

SimplificaciónUna regla didáctica
Una tabla de cinco productos y un umbral de lluvia no dicen de verdad qué está en temporada. En el proyecto real lo calcula el servidor. Aquí sirve para practicar el flujo de datos.
where filtra la lista: deja los productos disponibles (RN-04) cuyo clima coincide con el de hoy.
const temporada = {
  'Tomate chonto': 'templado',
  'Aguacate hass': 'templado',
  'Papa criolla': 'lluvioso',
  'Panela': 'lluvioso',
  'Mora': 'lluvioso',
};

String climaDelDia(double lluvia) {
  return lluvia > 0 ? 'lluvioso' : 'templado';
}

List<Producto> sugeridos(List<Producto> productos, String clima) {
  return productos
      .where((p) => p.disponible && temporada[p.nombre] == clima)
      .toList();
}

Integrador

El catálogo con clima, de punta a punta

Future<void> cargar() async {
  setState(() {
    estado = Estado.cargando;
  });
  try {
    final productos = await pedirProductos();
    final clima = await pedirClima();
    if (!mounted) return;
    final tipo = climaDelDia(clima.lluvia);
    final lista = sugeridos(productos, tipo);
    setState(() {
      tipoClima = tipo;
      resumenClima =
          'Hoy en Envigado: ${clima.temperatura} °C, lluvia ${clima.lluvia} mm';
      recomendados = lista;
      estado = lista.isEmpty ? Estado.vacio : Estado.listo;
    });
  } on TimeoutException {
    mostrarError('La respuesta tardó demasiado.');
  } on SocketException {
    mostrarError('No hay conexión a internet.');
  } catch (e) {
    debugPrint('Error inesperado: $e');
    mostrarError('Algo salió mal. Intenta de nuevo.');
  }
}
Future<Clima> pedirClima() async {
  final url = Uri.parse(
    'https://api.open-meteo.com/v1/forecast'
    '?latitude=6.17&longitude=-75.58'
    '&current=temperature_2m,precipitation,weather_code',
  );
  final respuesta = await http.get(url).timeout(const Duration(seconds: 5));
  if (respuesta.statusCode != 200) {
    throw Exception('El servidor respondió ${respuesta.statusCode}');
  }
  return Clima.fromJson(jsonDecode(respuesta.body));
}

void mostrarError(String mensaje) {
  if (!mounted) return;
  setState(() {
    mensajeError = mensaje;
    estado = Estado.error;
  });
}
