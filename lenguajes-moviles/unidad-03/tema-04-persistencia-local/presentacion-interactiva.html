Persistencia local en Flutter: preferencias, SQLite y almacenamiento seguro para que el catálogo siga ahí aunque no haya señal.

El problema

Sin señal en la finca

Doña Rosa abre la app en la vereda. No hay señal. Ayer vio los precios, pero hoy la pantalla dice que no pudo cargar nada.

La meta de este tema: que la app recuerde el último catálogo y lo muestre sin conexión, con un aviso claro y sin dejar confirmar pedidos.

RN-06. El catálogo guardado sin conexión permite consultarlo, pero no confirmar un pedido nuevo con él.

Dónde viven los datos de una app

¿Qué se pierde y qué se queda cuando cierras la app?

Predice antes de ver

¿Qué queda al cerrar la app?

Al abrir otra vez, sin señal, ¿qué tiene la lista productos?

Las variables viven en la memoria RAM. Al cerrar la app, el sistema la libera y todo se borra. Para que algo sobreviva hay que escribirlo en el almacenamiento del teléfono.

El mapa del tema

Tres herramientas, tres trabajos

shared_preferencesUn dato pequeño con nombre
Guarda pares clave y valor: textos, números, booleanos. Ideal para ajustes como el municipio o el tema.
sqfliteTablas con muchas filas
Usa SQLite, una base de datos que vive en un archivo dentro del teléfono. Ideal para listas como el catálogo.
flutter_secure_storageSecretos bajo llave
Guarda datos sensibles cifrados con ayuda del sistema: Keystore en Android y Keychain en iOS.
Ninguna reemplaza a las otras. Cada dato va donde su tamaño y su riesgo lo piden.
02

StatefulWidget, repasado completo

¿Cómo sabe Flutter que debe volver a dibujar la pantalla?

Parte 2. Concepto

El estado es lo que cambia

El estado son los datos que cambian mientras miras la pantalla: cuántos tomates llevas, la lista que llegó, si hay o no conexión.

StatelessWidget

Se dibuja con lo que recibe y no cambia por sí solo. Como un menú impreso.

StatefulWidget

Guarda datos que cambian y se vuelve a dibujar cuando se lo pides. Como una pizarra.

¿Por qué no todo es Stateful?Lo simple se queda simple
Un título o un ícono nunca cambian: un StatelessWidget basta y es más fácil de leer. Usa StatefulWidget solo donde algo cambia.

Una nota con nombre

Guardan pares clave y valor: escribes con un nombre y lees con el mismo.

final prefs = SharedPreferencesAsync();

await prefs.setString('municipio', 'Rionegro');
await prefs.setBool('oscuro', true);

Qué tipos aceptaSolo datos sencillos
int, double, bool, String y List<String>. Cada tipo tiene su par: setInt y getInt, setBool y getBool.

04

SQLite sin miedo

¿Cómo se guarda una lista de productos para leerla después?

Parte 4. Concepto

Una tabla es una hoja de cuaderno

SQLite guarda los datos en un archivo, catalogo.db, organizados en tablas.

FilaUn producto completo
Cada fila es un registro: la panela con su id, nombre, precio y disponibilidad.
ColumnaUn campo con tipo
Cada columna tiene nombre y tipo: precio INTEGER.
Clave primariaEl id que no se repite
La clave primaria identifica cada fila. Dos productos no pueden tener el mismo id.

Traducción

Dart y SQLite usan tipos distintos

SQLite no tiene tipo booleano. Guardas true como 1 y false como 0, y al leer conviertes de vuelta.
CREATE TABLE productos(
  id INTEGER PRIMARY KEY,
  nombre TEXT,
  precio INTEGER,
  disponible INTEGER
)

Simulador de SQLite

Habla con la tabla

Predice antes de ejecutar

DELETE sin WHERE

DELETE FROM productos
Tabla productos

La tabla tiene cinco productos. ¿Qué borra esta sentencia?

Sin WHERE, DELETE borra todas las filas. La tabla sigue existiendo, vacía. Para borrar la tabla misma se usa DROP TABLE. Lo mismo pasa con UPDATE: sin WHERE cambia todas las filas.

Reto

Ordena el catálogo con SQL

El productor ya no tiene aguacate (RN-04). Márcalo con disponible = 0 sin tocar los demás.

Sube el precio de la panela a 6000.

SQLite también tiene migraciones, transacciones, lotes (batch) e índices. Existen; hoy no los necesitas.

Abrir la base

Database? _base;

Future<Database> abrirBase() async {
  _base ??= await openDatabase(
    join(await getDatabasesPath(), 'catalogo.db'),
    version: 1,
    onCreate: (db, version) {
      return db.execute(
        'CREATE TABLE productos('
        'id INTEGER PRIMARY KEY, '
        'nombre TEXT, '
        'precio INTEGER, '
        'disponible INTEGER)',
      );
    },
  );
  return _base!;
}

Traducción

De Producto a Map y de vuelta

class Producto {
  final int id;
  final String nombre;
  final int precio;
  final bool disponible;

  const Producto({
    required this.id,
    required this.nombre,
    required this.precio,
    required this.disponible,
  });
}
// Producto a Map: así lo entiende SQLite
Map<String, Object?> toMap() {
  return {
    'id': id,
    'nombre': nombre,
    'precio': precio,
    'disponible': disponible ? 1 : 0,
  };
}
// Map a Producto: así lo entiende la pantalla
factory Producto.fromMap(Map<String, Object?> mapa) {
  return Producto(
    id: mapa['id'] as int,
    nombre: mapa['nombre'] as String,
    precio: mapa['precio'] as int,
    disponible: mapa['disponible'] == 1,
  );
}

Future<List<Producto>> leerCatalogo() async {
  final db = await abrirBase();
  final filas = await db.query(
    'productos',
    where: 'disponible = ?',
    whereArgs: [1],
  );
  return [for (final fila in filas) Producto.fromMap(fila)];
}

06

Almacenamiento seguro

¿Dónde guardas algo que no quieres que nadie más lea?

Parte 6. Concepto

Una nota o una caja fuerte

CifrarVolverlo ilegible
Cifrar convierte el dato en texto ilegible. Solo la llave lo devuelve a su forma original.
Keystore y KeychainLas bodegas del sistema
En Android, el Keystore guarda la llave y no la deja salir. En iOS, el Keychain guarda el dato protegido.
Las preferencias son una nota en la nevera: cualquiera que entre la lee. La caja fuerte necesita la llave, y la llave la tiene el sistema.

Future<void> cerrarSesion() async {
  await almacen.delete(key: 'ficha_sesion');
